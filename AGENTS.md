# AI Design

Публичный скилл фронтенд-дизайна семейства AI Мастерской: интервью о вкусе и стиле, показ примеров на панели, сборка дизайна сайта без шаблонности ИИ; работает отдельно и в связке с AISpa.

Стек: Python 3.9+ только стандартная библиотека, HTML/CSS/JS без сборки. Архитектура и договорённости — `docs/architecture.md`; решения «почему» — `docs/adr/`; словарь — `CONTEXT.md`.

## Команды

Из корня репозитория.

| Команда | Что делает |
|---------|------------|
| `python3 -B -m unittest discover -s tests` | все тесты (сейчас 299, число растёт) |
| `python3 -B -m unittest tests.test_ad` | один файл тестов (`test_ad`, `test_check`, `test_setup`, `test_backup`, `test_scaffold`, `test_designsystem`, `test_rules`, `test_media`, `test_shots`, `test_examples`, `test_knowledge`, `test_process`, `test_release`) |
| `python3 skills/aidesign/tools/check.py skills/aidesign/examples` | проверка на шаблонность ИИ; ждём «Находок: 0»; флаги `--json`, `--rules` |
| `python3 tools/public-export.py --out <новая папка>` | чистая выгрузка для публикации; ждём «Находок: 0»; берёт только файлы из git — сначала коммит |
| `python3 skills/aidesign/tools/setup.py doctor` | что стоит на компьютере; `plan <ids> --os mac\|windows\|linux` — команды установки без установки |
| `python3 .aidesign-work/ad.py init --slug S --title "…" --mode interview --questions one --entry new --skill-dir "$SKILL_DIR"` | учебный прогон скилла (после копирования инструментов по сниппету из `skills/aidesign/phases/0-start.md` §4) |
| `python3 .aidesign-work/ad.py --stop` | погасить сервер панели |

## Где что

- `skills/aidesign/SKILL.md` — оркестратор скилла: таблица этапов, неснимаемые правила; версия в `metadata.version`.
- `skills/aidesign/phases/0-start.md … 6-handoff.md` — правила по этапам; `phases/dashboard-template.html` — шаблон панели (руками в прогоне не правится).
- `skills/aidesign/prompts/{preview,build,critic}.md` — задания субагентам.
- `skills/aidesign/tools/ad.py` — учёт прогона, `state.js`, сервер панели; `tools/check.py` — правила шаблонности (`RULES`, `scan()`).
- `skills/aidesign/tools/setup.py` — проверка и установка программ (ключ команд — пакетный менеджер); `backup.py` — копии проекта и откат (ссылки не пишутся насквозь, ничего не удаляется); `scaffold.py` — структура проекта; `designsystem.py` — `tokens.json`, проверка «мимо токенов», архив (кладёт рядом с проектом); `rules.py` — блок `aidesign` в памяти проекта: подраздел «Сейчас» переписывает `ad.py` сам после каждого события, на готовом сайте — только после первой копии «до». Все копируются в `.aidesign-work/` на `init`.
- `skills/aidesign/tools/media.py` — генераторы (распознать по отпечатку инструментов, подключить), найти скиллы про медиа, скачать (`fetch`, без перезаписи, SVG по белому списку), подготовить (`prep` через ffmpeg/cwebp), опись `assets/media.json`; каталог — `knowledge/медиа/генераторы.json`. Бюджет — `ad.py media budget|spend|check` (одна единица, `check` 1 — спросить человека). `shots.py` — снимки превью 1280/390. `ad.py --serve-http PORT --directory DIR` — сервер с Range для показа сайта (видео по прокрутке без Range не перематывается).
- `skills/aidesign/knowledge/медиа/` — промпты по инструкциям владельца (пересказ под MIT с его разрешения 19.11), рецепты «кодом вместо генерации».
- `skills/aidesign/phases/figma.md` — Figma, читается только после согласия человека.
- `skills/aidesign/knowledge/sources.json` — реестр источников; порядок пополнения новым скиллом — `docs/пополнение.md` (тест сверяет реестр, `THIRD_PARTY_NOTICES.md`, README и шапки).
- `skills/aidesign/knowledge/INDEX.md` — маршрут по базе знаний; `язык/`, `движение-и-медиа/`.
- `skills/aidesign/examples/` — 7 демо-страниц и `INDEX.json`.
- `tools/public-export.py` — единственный способ выгрузки для публикации.
- `tests/` — по файлу на модуль; `tests/test_release.py` сторожит версии, чистоту дерева, зеркальность README.
- `.github/workflows/ci.yml` — только ручной запуск.
- `.sources/` и `.aidesign-work/` — в `.gitignore`, не коммитятся.

## Подводные камни

- Версия в `skills/aidesign/SKILL.md` обязана совпадать с верхней записью `CHANGELOG.md` (тест).
- `README.md` (английский) и `README.ru.md` зеркальны; всё, что видит пользователь скилла, — по-русски.
- Слова об основе семейства — только в `LICENSE` и последней строке обоих README; тест следит.
- В публичных файлах нет путей домашней папки, имён людей, ключей; `.aispa-work/` и `БРИФ.md` содержат такие пути — публиковать только через `tools/public-export.py`.
- Новый или близкий к источнику файл знаний начинается с HTML-комментария об источнике и лицензии; он же должен быть в `THIRD_PARTY_NOTICES.md` и README.
- Превью на панели видны только по `http`, не по `file://`.
- AISpa считает `AGENTS.md` без её меток `aispa:start/end` файлом пользователя: в проекте, где AI Design создал `AGENTS.md` только со своим блоком `aidesign`, AISpa в него не пишет, а в конце предлагает дополнения. Правка AISpa 1.0.3 (подсказка `/aidesign`) — в другом репозитории.
- Оболочка Bash у агента — zsh: переменная со списком путей не дробится на слова; передавай пути явно.
- Инструменты, которые трогают файлы человека (`backup.py`, `scaffold.py`), тестируются только во временных папках; откат и перенос — с `--yes` и после вопроса человеку.
- Превью всегда настоящие (настоящий приём на настоящем материале); генерация в превью — только в трёх случаях (`3-previews.md` §3), и все тексты про это должны совпадать — тест `test_process` сторожит.
- Не меняй логику `ad.py` относительно форка `ap.py` без причины: время, ожидание, сервер, `write_snapshot` взяты как есть.

## Как здесь работает AISpa

Сборка ведётся навыком `/aispa`. Требования, спецификация и задачи — в `.aispa-work/`.
Прогресс — `.aispa-work/dashboard.html`. Требование из `manifest.md` может снять
только пользователь. Прерванную сборку продолжает «продолжи AISpa».

### Правка без AISpa

Мелкий баг или доводка после сборки — обычная сессия, без прогона.

Сначала прочитай:
1. `.aispa-work/PROGRESS.md` — что не доделано, известные баги, о чём договорились с пользователем.
2. Что правили после последней сборки — первая строка таблицы в «История git».
3. Только если правка их касается: почему сделано так — `docs/adr/`; что значат слова — `CONTEXT.md`;
   что именно просили — `manifest.md` в папке сборки (указана в начале `PROGRESS.md`).

После правки:
- коммит — по правилам из «История git»;
- строка в «Правки без AISpa» в `PROGRESS.md`: дата — что — почему;
- починенный пункт из «Не доделано» или «Известные баги» — удали;
- договорились с пользователем о том, что следующая сборка не должна пересматривать, —
  строка в «Договорились», его словами.

### История git

Целиком не читай — бери срез под вопрос:

| Вопрос | Команда |
|---|---|
| что правили после последней сборки | `git log --oneline "$(git log -1 --format=%h --grep='^AISpa: сборка сдана')"..HEAD -- . ':(exclude).aispa-work'` |
| всё, что делали ради требования | `git log --oneline --grep="R02"` |
| история файла | `git log --oneline -10 -- <файл>` |
| когда появился или исчез код | `git log --oneline -S "<фрагмент>"` |
| почему строка такая | `git blame -L <с>,<по> <файл>`, затем `git show <sha>` |
| что внутри коммита | `git show --stat <sha>` |

Срез длиннее ~30 коммитов — отдай его субагенту и возьми выжимку в десять строк.

Коммит: заголовок — что (`fix: даты в одном формате`), тело — почему, трейлер
`--trailer "Requirements: R02"`, если правка касается требования из `manifest.md`.
Заголовок `AISpa: сборка сдана` пишет только AISpa — по нему находят последнюю сборку.
