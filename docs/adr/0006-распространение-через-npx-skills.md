# 0006. Распространение через `npx skills`, без обновителя и без запрета вызова моделью

## Контекст

AISpa 1.0.x ставится через `npx skills`, но тянет за собой обновитель из Release-архивов, мост с версиями 0.x и запрет `disable-model-invocation`. У AI Design наследия 0.x нет. В пользовательской копии AISpa этот запрет приходится снимать вручную после каждого обновления.

## Решение

Репозиторий `skills/aidesign/` ставится и обновляется только командами `npx skills add` и `npx skills update aidesign -g`. Обновителя, Release-архивов и установщика нет. При старте скилл сравнивает свою версию в `SKILL.md` с версией на GitHub и печатает строку `↑`, если вышла новая; выключатель `AIDESIGN_NO_UPDATE_CHECK`. В `SKILL.md` нет `disable-model-invocation`, модель может запустить скилл по просьбе человека. Версия в двух местах: `metadata.version` и верх `CHANGELOG.md`, тест их сверяет.

## Почему

- Обновитель как у AISpa: вес и тесты на поддержку наследия, которого здесь нет. Отвергнуто.
- Схема семейства с git clone, симлинком и датой-версией: ставить сложнее, человек не открывает терминал. Отвергнуто.
- Запрет вызова моделью: тогда скилл не запустить по обычной просьбе, а `npx skills update` возвращает флаг и его снова надо снимать руками.

## Последствия

- `npx skills update` сравнивает версии, а не файлы: правка без нового номера версии до пользователей не дойдёт.
- Откатиться на прошлую версию нечем, кроме переустановки.
- Обновление посреди прогона не предусмотрено: только между прогонами.
- Модель может запустить скилл без слов человека, и поэтому интервью и «Ждём тебя» стоят до любой сборки.
