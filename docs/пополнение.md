# Пополнение: как добавить в AI Design новый найденный скилл

Порядок для того, кто нашёл новый дизайн-скилл, инструмент или свод правил и хочет перенести его знания в AI Design. Шаги идут строго по очереди: знание без лицензии и без записи в реестре в скилл не попадает.

## 1. Нашли источник

Запишите адрес репозитория и коммит, с которого берёте (`git clone` в `.sources/<тема>/` — папка в `.gitignore` и не коммитится). Проверьте, нет ли его уже в реестре `skills/aidesign/knowledge/sources.json`: есть — дополняйте ту же запись, вторую не заводите.

## 2. Лицензия — до чтения содержимого

Найдите файл `LICENSE` (или `LICENSE.txt`, поле `license` в `SKILL.md`, раздел README) и строку копирайта.

| Что нашли | Что можно |
|---|---|
| MIT, Apache-2.0 и похожие открытые | переносить текст пересказом или переводом с шапкой «Источник … Изменено …»; для Apache-2.0 пометка «Изменено» обязательна, его `NOTICE` переносится дословно |
| лицензия только словами в README, файла нет | только идеи своими словами, шапка «По мотивам» |
| файла лицензии и слов о ней нет, проприетарная, CC BY-SA, «Pro», платный каталог | ничего не копировать; можно назвать как путь, которым человек идёт сам |

Фото, логотипы, файлы с описанием чужих брендов, код библиотек и платные пресеты не переносятся никогда, даже под открытой лицензией.

## 3. Что копируем, что только идеями

Решите для каждой части источника: **текст** (пересказ или перевод близко к оригиналу), **идея** (мысль своими словами) или **ничего**. Спорное — идеей. Если правило источника спорит с тем, что уже есть в базе, решение записывается в `knowledge/язык/решения-споров.md`, а не молча.

## 4. Куда в knowledge/

Ищите место по `skills/aidesign/knowledge/INDEX.md`: подходящий файл есть — дополните его раздел; нет — новый файл в `язык/` или `движение-и-медиа/`, с разделами «Когда читать», правила с «почему», «Не делать». Новый файл сразу получает строку в `knowledge/INDEX.md` (в маршрут и в «Все файлы базы»), иначе агент его не найдёт.

## 5. Шапка атрибуции

Первая строка файла знаний — HTML-комментарий:

- текст: `<!-- Источник: <владелец/репо>/<путь>, <SPDX>, © <копирайт>. Изменено: <что>. -->`
- идея: `<!-- По мотивам: <владелец/репо> (<SPDX>) -->`

Источников несколько — по строке на каждый, подряд с первой строки. Свой текст без источника — `<!-- По мотивам: alexfisenkov/aidesign (MIT) — свой текст -->`.

## 6. Реестр, уведомления, README

Одним заходом, в трёх местах:

1. `skills/aidesign/knowledge/sources.json` — запись `{id, title, repo, url, license, copyright, commit, form, taken, files}`; в `files` — каждый файл скилла, в шапке которого назван репозиторий.
2. `THIRD_PARTY_NOTICES.md` — раздел `### Название — \`владелец/репо\` (коммит)` с полями «Лицензия», «Копирайт», «Адрес», «Что взято» и, если нужно, «Не взято». Новая лицензия, которой ещё нет в конце файла, — её полный текст туда же.
3. Оба README (`README.md` и `README.ru.md`, зеркально) — строка в таблице «Из чего собран» с тем же адресом, что в `url` реестра.

## 7. Оснащение, а не знания

Источник — программа, которую скилл должен ставить и уметь запускать (как Playwright или ffmpeg), — это не запись в реестре знаний, а строка в `TOOLS` файла `skills/aidesign/tools/setup.py` (официальный способ установки на трёх ОС, проба версии) и рецепт в `knowledge/инструменты.md`. Другие MCP и скиллы AI Design не ставит.

## 8. Тесты и выгрузка

```bash
python3 -B -m unittest discover -s tests
python3 tools/public-export.py --out <новая пустая папка>
```

Тесты сверяют реестр с `THIRD_PARTY_NOTICES.md`, обоими README и шапками атрибуции, индекс знаний — с файлами на диске. Выгрузка должна закончиться строкой «Находок: 0»; строки «Не в git, не выгружено» значат, что новые файлы ещё не закоммичены. Затем — запись в `CHANGELOG.md` и новая версия в `skills/aidesign/SKILL.md`.
