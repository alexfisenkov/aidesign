# Задание: сборка по выбранному направлению

Этот файл — для субагента, который собирает страницу или сайт (или свою часть — тогда оркестратор назвал, какие файлы твои). Оркестратор передал путь к этому файлу и входные данные: корень проекта, файл выбранного превью и папку его круга, `DESIGN.md`, `design-system/`, `direction.md` с разделами «Маршрут сборки» и «Правки к выбранному», `vkus.md`, `brief.md`, `media-plan.md` и опись `assets/media.json`, адрес локального сервера, на готовом сайте — `audit.md`, и абсолютный путь к `<skillDir>`.

**Ты доводишь выбранный вариант, а не собираешь сайт заново.** Человек выбрал превью, которое видел живым: его файл — основа страницы: **тот же код**, та же разметка первого экрана, тот же главный приём и материал; ты переводишь его стиль на токены, достраиваешь все разделы и вносишь «Правки к выбранному». Переписать первый экран «по мотивам» — не то, что выбрал человек.

**Не вызывай скиллы и слэш-команды и не запускай своих агентов.** Ничего не отправляй наружу, не публикуй, не деплой, не делай `git push`, ничего не покупай и не запускай генерацию медиа — её ведёт оркестратор по бюджету; нужно новое медиа — назови место в отчёте. Пиши только в файлы, которые тебе назвали; нужно тронуть чужое — верни это в отчёте.

## Прочитай

1. `DESIGN.md` — это закон: токены, шрифты, сетка, компоненты, движение, фото, «Чего нельзя». `design-system/` — откуда брать стиль: `tokens.css` (значения), `styleguide.html` (готовые компоненты), `README.md` (как подключить). Выбранное превью — не картинка для вдохновения, а код, с которого начинается страница; сайт продолжает его, а не изобретает заново.
2. `direction.md` → «Маршрут сборки» — файлы `<skillDir>/knowledge/…`, которые нужно прочитать. Читай только их, по нужному разделу.
3. `vkus.md` и `brief.md` — тон, тексты, что точно не про человека.
4. На готовом сайте — `audit.md` (опись «не сломать») и `<skillDir>/knowledge/движение-и-медиа/готовый-сайт.md`, разделы 3 и 4.

## Правила

- **Стиль — только из `design-system/tokens.css`**: каждая страница подключает его первым, весь стиль — через `var(--…)`, ни одного значения цвета или шрифта в своём CSS. Новый цвет, шрифт, радиус, тень, которых нет в `tokens.css`, — не вводи; нужен — верни в отчёте, оркестратор допишет токен и правила. Тебе поручили саму дизайн-систему — пиши `tokens.css`, `styleguide.html`, `README.md` по `DESIGN.md` и выбранному превью.
- **Одна ведущая стилистика**, не больше одного громкого приёма на экран (`<skillDir>/knowledge/язык/сочетание.md`). Каталог `<skillDir>/knowledge/язык/антипаттерны.md` — что не делать; спор правил — `<skillDir>/knowledge/язык/решения-споров.md`.
- **Текст — только человека.** Нет текста, цены, телефона, адреса, отзыва — видимая заглушка `[ЦЕНА — впиши]`, никогда правдоподобная выдумка.
- **Медиа** — только из описи `assets/media.json` и папок `assets/img/`, `assets/video/`: свои файлы человека, сгенерированные для него и подготовленные оркестратором, код; нет файла для места — плашка в пропорции будущего фото с подписью «что здесь будет» и строка в `PLACEHOLDERS`. Материал из папки круга превью заменяется подготовленными файлами из `assets/`. У каждой картинки — `alt` из описи, у видео — `poster`, `muted`, `playsinline`. Без чужих фото, логотипов, стоковых людей под видом «наших».
- **Главный приём выбранного превью остаётся настоящим**: видео идёт за прокруткой, канвас рисует, эффект мыши отзывается. Видео — прямо через `<video src>` (работает и по `file://`), `fetch` → `Blob` — только улучшение по http с возвратом к `src`; всё, что по `file://` не загрузится, — с плашкой «Открыто как файл… Откройте: http://localhost:ПОРТ/…» (`<skillDir>/knowledge/движение-и-медиа/видео-в-сайт.md`).
- **Стек проекта.** Новый сайт — самый простой стек, который выдержит задачу (одна страница — HTML, CSS, ванильный JS без сборки). Готовый сайт — его фреймворк, его структура, его движок анимации. Новая зависимость — только если без неё приём невозможен, и строкой в отчёте.
- **Движение** — по разделу «Движение» `DESIGN.md`: прогрессивное улучшение поверх работающей страницы; колесо не перехватывать; `prefers-reduced-motion: reduce` — всё на месте, без потери содержимого.
- **Телефон и доступность:** работает на 390 и 1280, касание вместо наведения, цели касания от 44px, видимый фокус, контраст текста от 4.5:1, `alt` у картинок, без горизонтальной прокрутки.
- **Готовый сайт:** то, что работает, продолжает работать. Не переименовывать `id`, классы, `data-*`, поля форм, адреса ссылок из описи; новый класс — рядом со старым. Не удалять скрипты аналитики, виджеты, файлы. Меняй слоями: токены → отступы → компоненты → раскладка → движение и медиа; после каждого слоя — проверки проекта.

## Проверь до сдачи

- `python3 <skillDir>/tools/check.py <свои файлы>` — ноль находок; осознанный выбор направления — комментарий `aidesign-ignore: <id> — причина`.
- `python3 <skillDir>/tools/designsystem.py check <свои файлы> --ds design-system` — ноль находок: стиль не мимо токенов.
- Собственные проверки проекта (тесты, сборка), если они есть — их командами.
- Если доступен браузер или Playwright (`<skillDir>/knowledge/инструменты.md`, раздел 2) — страница **по http** на 390 и 1280: ничего не вылезает, всё нажимается, нет ошибок в консоли, главный приём работает (видео: `readyState` не меньше 2, `currentTime` идёт за прокруткой). Снимки — в папку прогона, не в папку сайта.
- Готовый сайт — пройди опись «не сломать» из `audit.md`.

Красное, которое не можешь починить, не сдаётся как готовое — верни с причиной.

## Верни

