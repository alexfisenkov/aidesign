# Справочник: стили, палитры, шрифтовые пары, отрасли, лендинги

## Когда читать

- После интервью или разбора референсов, когда нужны **стартовые кандидаты** для трёх превью.
- Когда человек назвал только дело («кофейня», «юрист») и пару слов о характере.
- При пополнении справочника: раздел «Как пополнять».

Справочник подсказывает, но не решает. Порядок по спору 7 (`../язык/решения-споров.md`): слова человека → профиль вкуса `vkus.md` → референсы → отрасль как стартовая гипотеза. Три превью берут **разные** кандидаты (`directions`), а не одну отраслевую формулу.

## Как пользоваться

```bash
python3 pick.py "кофейня уютная тёплая"            # кандидаты с причинами
python3 pick.py "юрист строгий" --json --n 3        # для агента
python3 pick.py "барбершоп смелый" --dark           # тёмная тема первой
python3 pick.py "кофейня" --tokens .aidesign-work/<dir>/pick/2-tokens.css --direction 2   # черновик токенов
python3 pick.py list industries                     # styles | palettes | pairs | industries | landings | fonts
python3 pick.py validate                            # проверка всего справочника, ждём «Нарушений: 0»
```

`pick.py` лежит в `tools/` скилла; данные ищет в `--data <папка>`, затем в переменной `AIDESIGN_REFERENCE`, затем в `../knowledge/справочник` от себя. Поиск — по-русски: слова приводятся к основе («кофейню», «кофейни» → «кофейн»), так что формы слова не важны.

Что выдаёт: отрасль и по каким словам узнана; сработавшие правила; ограничения («помнить: …»); по три стиля (разных семейств), палитры (разных групп), шрифтовые пары (разные заголовочные шрифты) и паттерна лендинга — у каждого «почему»; три направления для превью; приметы шаблона, которых избегать.

`--tokens` пишет черновик `tokens.css` в формате `designsystem.py` (`--color-*`, `--font-display`, `--font-body`, `--radius-*`, `--space-*`, `--shadow-card`, `--motion-*`; тёмная тема — `[data-theme="dark"]` и `prefers-color-scheme`). Это заготовка для этапа «Сборка», её доводят под выбранное направление и только потом переносят в `design-system/tokens.css`. Файл, написанный не справочником (без шапки «Черновик токенов AI Design из справочника»), `pick.py` не перезаписывает: код 2 и подсказка; заменить его можно только явным `--force`.

### Роли палитры

Как в токенах: `--color-<роль>`.

`bg` (холст), `surface` (карточки и поля), `text`, `muted` (вторичный текст), `border` (граница полей и кнопок), `divider` (декоративная линия), `primary` и `on-primary` (главное действие и текст на нём), `accent` и `on-accent`, `ring` (кольцо фокуса), `danger` и `on-danger`, `success` (текст статуса), `warning` и `on-warning`.

Контраст, который проверяет `validate` в светлой и тёмной теме:

- 4.5:1 — `text` и `muted` на `bg` и `surface`; текст на `primary`, `accent`, `danger`, `warning`; `success` на `bg`.
- 3:1 — `border` на `bg`; `ring` на `bg` и `surface`; `primary` на `bg`.

Сверх этого: `muted` не контрастнее `text`; `danger` не зелёный; синих «как Tailwind» (`#2563EB`, `#3B82F6`, `#6366F1` и ближе ΔE 10 в OKLab) среди `primary`/`accent` — не больше 5 % палитр. Цвета каждой палитры — светлая и тёмная тема по отдельности — проходят `check.py` (лежит рядом с `pick.py`): любая находка шаблонности (`cream-terracotta`, `dark-neon` и другие) — нарушение.

Тёмная тема выводится из светлой (`derive_dark`): фон и поверхности — ступенями того же оттенка, текст светлый, акценты светлее и тише (насыщенность не выше 0.75 по HSL, чтобы на почти чёрном фоне не было «кислоты»), затем светлота подгоняется до нужного контраста. У палитр с `prefer: dark` наоборот: хранится тёмная, светлая выведена.

### Правила отраслей — закрытая грамматика

`rules` — объект «условие → список действий». Данные ничего не исполняют: условия и действия берутся только из закрытых списков `pick.py`.

- **Условия:** `must_have` (всегда) и `if_luxury`, `if_budget`, `if_kids`, `if_trust`, `if_warm`, `if_bold`, `if_calm`, `if_night`, `if_dark`, `if_light`, `if_booking`, `if_reading`, `if_portfolio`, `if_eco`, `if_minimal`, `if_classic`, `if_modern`, `if_playful`, `if_tech`. Каждое срабатывает на основы слов запроса (`CONDITIONS` в `pick.py`): «уютная» → `if_warm`, «строгий» → `if_trust`.
- **Действия:** `style:<id стиля>`, `pattern:<id лендинга>`, `mode:dark|light`, `constraint:<id из constraints>`, `mood:<слово>` (добавляет слово в поиск палитр и пар).

Пример: `{"must_have": ["constraint:photo-led"], "if_night": ["mode:dark", "style:evening-lounge"]}`.

## Как пополнять

1. **Палитра.** Придумать имя, настроение и для чего она; выбрать четыре опорных цвета из предмета дела (фон, текст, основной, акцент) и получить остальные роли:
   `python3 pick.py make-palette --id rowan --name "Рябина" --bg "#FAF5F2" --text "#2A1512" --primary "#9E2A2B" --accent "#E9B44C"` (для тёмной — с `--dark-first`, опорные цвета тёмные). Вставить вывод в `палитры.json`, дописать `mood`, `for`, `tags`, `group`, `temperature`, `prefer`.
2. **Пара шрифтов.** Оба семейства должны быть в `google-fonts.json` (там только шрифты с кириллицей). Начертания — из их `styles`; `url` — вида `https://fonts.googleapis.com/css2?family=Имя+Шрифта:wght@400;700&family=…&display=swap` (статичный шрифт с одним начертанием — без `:wght@`). Неверную ссылку `validate` покажет вместе с правильной.
3. **Стиль.** `family` — существующий файл в `../язык/стили/`; `avoid` — якоря из `../язык/антипаттерны.md`.
4. **Отрасль.** Ключевые слова в нескольких формах («юрист, юристы, юридическая»); стили из трёх семейств, палитры из трёх групп и три пары — иначе три превью не будут разными.
5. После любой правки — `python3 pick.py validate` до «Нарушений: 0» и `python3 -B -m unittest tests.test_pick` из корня репозитория.
6. Обновить `google-fonts.json` — из метаданных Google Fonts (`github.com/google/fonts`, `METADATA.pb`): оставить только семейства с подмножеством `cyrillic`, без имён дизайнеров.

## Откуда устройство

Устройство справочника — машиночитаемые данные, подбор по отрасли с правилами закрытой грамматики, сторож контраста, вывод тёмной темы, метаданные Google Fonts — по мотивам UI UX Pro Max (nextlevelbuilder/ui-ux-pro-max-skill, MIT, © 2024 Next Level Builder). Метаданные шрифтов в `google-fonts.json` — данные Google Fonts в выборке этого проекта. Стили, палитры, пары, отрасли и паттерны лендингов — свои, по-русски и с кириллицей; их палитры и пары не переносились.

## Не делать

- Брать первую отраслевую тройку как решение: это гипотеза, интервью главнее.
- Ставить шрифт без кириллицы или «похожий» системный в превью.
- Править цвета палитры на глаз после `make-palette`: любая правка — снова через `validate`.
- Подставлять в паттерн лендинга выдуманные цифры и отзывы: только настоящие факты человека или видимая заглушка.
