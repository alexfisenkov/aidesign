# Движение: зачем, сколько и как

## Когда читать

- Перед сборкой любого превью или сайта, где что-то движется (а это почти всегда: наведение, нажатие, появление первого экрана).
- Перед `прокрутка-и-сцены.md`, `морфинг.md`, `курсор-и-микровзаимодействия.md`, `webgl-и-3d.md`: здесь общие правила, там приёмы.
- Когда человек в интервью ответил про движение: «спокойно», «живо», «как на award-сайтах», «навороченно».

## Главная мысль

Движение объясняет: что нажалось, что откуда взялось, куда смотреть, где ты сейчас. Плюс один авторский момент, который страница заслужила. Анимация без задачи — долг: она тормозит, отвлекает и делает сайт шаблонным. Перед сборкой напиши «тезис движения» в четыре строки:

1. **Главный момент** — одна последовательность или одно взаимодействие, которое запомнится (если оно вообще нужно).
2. **Непрерывность** — какие смены состояния и раскладки надо объяснить движением.
3. **Отклик** — какие кнопки, поля и переключатели отвечают на действие.
4. **Бюджет** — какие эффекты дорогие и как часто они работают.

Главный момент берётся из предмета страницы. Общее «появление снизу с затуханием», «приподнимание карточки» или «параллакс» тезисом не являются.

## Уровни движения под ответ человека

| Ответ в интервью | Что можно | Чего нет |
|---|---|---|
| «Спокойно», «строго», сервис, клиника, юристы | наведение и нажатие, появление первого экрана, смены состояний | сцены прокрутки, свой курсор, WebGL |
| «Живо», «современно» | всё выше + один момент в своей секции (см. `прокрутка-и-сцены.md`) | второй «громкий» приём на том же экране |
| «Навороченно», «как на Awwwards», портфолио, запуск продукта, игра, техника | всё выше + сцена прокрутки или WebGL-сцена или эффект курсора, морфинг переходов | больше одного громкого приёма на экран (`../язык/сочетание.md`), перехват колеса |
| Страница приложения, кабинет, админка | быстрый отклик, непрерывность (FLIP, View Transitions) | хореография загрузки, прелоадер, сцены |

Почему так: источники спорят. Taste запрещает магнитные кнопки, свой курсор и появление карточек при прокрутке; premium-frontend-ui требует их по умолчанию. Мы берём условие: громкие приёмы — только когда человек сам попросил «навороченно» или предмет страницы этого требует, и только по одному на экран. Окончательное правило спора — в `../язык/решения-споров.md`.

## Длительности и кривые

| Длительность | Для чего |
|---|---|
| 90–150 мс | мгновенный отклик: нажатие, наведение |
| 150–300 мс | обычная смена состояния: вкладка, переключатель, меню |
| 300–500 мс | смена раскладки, всплывающее окно, переход между видами |
| 500–800 мс | один авторский вход (первый экран, главный момент) |
| 1–1,2 с | весь вход первого экрана целиком, после чего он стоит |

- Уход быстрее входа (примерно на треть).
- Кривая входа — плавное торможение, например `cubic-bezier(0.16, 1, 0.3, 1)` или `cubic-bezier(0.22, 1, 0.36, 1)`. Для обычных шагов интерфейса — одна кривая на весь сайт.
- Пружина и «отскок» — только если это часть характера (игривый бренд), и никогда по привычке. Кривая, которая перелетает отметку, на деловом сайте выглядит дёшево.
- Линейная кривая — только для бесконечных циклов и для анимации, привязанной к прокрутке.
- Каскад (stagger) — когда список появляется как список. Общая задержка всего каскада — не больше 240–300 мс, иначе последний элемент ждёт.

## Что анимировать

- По умолчанию `transform` и `opacity`: их считает видеокарта, раскладка не пересчитывается.
- Не анимируй `width`, `height`, `top`, `left`, `margin`, `padding` для перемещения и раскрытия: это пересчёт раскладки на каждом кадре и рывки на телефоне. Раскрытие блока — через FLIP, `grid-template-rows: 0fr → 1fr` или `transform`.
- Дороже, но допустимо в ограниченной области: `clip-path` (шторка, маска), `filter` (проявление фото, размытие фокуса), цвет, позиция градиента. Держи такие эффекты в одной изолированной области.
- `will-change` — только на время анимации и только на том, что движется. «На всякий случай» на всех элементах — это лишняя память.

## Чем делать

| Задача | Инструмент | Почему |
|---|---|---|
| Наведение, нажатие, смена состояния | CSS `transition` | без JS, сам откатывается |
| Короткая последовательность, вход первого экрана | CSS `@keyframes`, `@starting-style` для появления из `display: none` | без зависимостей |
| Прерываемое, с динамическими значениями | Web Animations API (`element.animate`) | отменяется и разворачивается |
| Таймлайны, сцены прокрутки, SVG-морф, разбиение текста | GSAP (ScrollTrigger, Flip, MorphSVG, SplitText) | все плагины бесплатны, в том числе для коммерческих сайтов |
| Анимация от прокрутки без JS | CSS `animation-timeline: scroll() / view()` за `@supports` | дёшево, но нужен запасной вариант для старых браузеров |
| Переходы между состояниями и страницами | View Transitions API | см. `морфинг.md` |

GSAP: ставь из npm (`npm install gsap`) или подключай с CDN. Код самой библиотеки в репозиторий проекта и в скилл не клади: лицензия GSAP не открытая (бесплатная Standard License, см. https://gsap.com/licensing/). Сгенерированный код, который вызывает GSAP, разрешён. Не добавляй библиотеку ради эффекта, который чисто делается на CSS.

## Первый экран: вход

Один раз при загрузке: заголовок по строкам (каждая строка около 700 мс, строки через 60–80 мс), затем подзаголовок и кнопки (около 500 мс, сдвиг 12 px), картинка «оседает» с масштаба 1,03–1,05 до 1. Всё укладывается примерно в 1,1 с, дальше первый экран стоит.

- Текст виден без скриптов: прятать слова можно только классом, который ставит скрипт, и с таймером-страховкой (если скрипт опоздал больше чем на 700 мс, текст просто появляется).
- Фото первого экрана не прячется и не проявляется из прозрачности — только лёгкое «оседание».
- Второго входа и повторного входа при прокрутке нет.

## Первый экран и шапка

- Первый экран во всю высоту (`min-height: 100svh` или `100dvh`, не `100vh` — на телефоне адресная строка обрезает низ) — когда первый экран и есть главный кадр: фото, видео, сцена. Для сервиса и приложения обычно лучше первый экран, из-под которого виден следующий блок: человек понимает, что дальше есть содержание.
- Шапка, которая прячется при прокрутке вниз и возвращается при прокрутке вверх, — уместна на длинных страницах с медиа; переход 200–250 мс по `transform`, при reduced-motion — без сдвига (появляется и исчезает). На коротких страницах и в приложениях шапка стоит.

## Прелоадер — только по условию

Прелоадер оправдан, если без него будет хуже: тяжёлая WebGL-сцена или 3D-модель, которой нужно 1–3 с, или прокрутка по кадрам, где без первых кадров сцена пустая. Тогда:

- он показывает реальный прогресс, а не таймер;
- первый кадр (постер) уже стоит под ним;
- уход прелоадера — короткий (400–700 мс) и связан с первым экраном (шторка уходит туда, где начинается заголовок);
- при повторном визите и при reduced-motion его нет.

На обычной странице, в кабинете, в документации, на странице сервиса прелоадера нет: заставлять человека ждать хореографию — минус.

## Наведение

- Наведение не сдвигает соседей и не уводит цель из-под курсора. Элемент стоит, двигается его внутренняя часть: карточка приподнимается внутренним слоем на 2 px, фото внутри рамки увеличивается до 1,02–1,03 за 600 мс (уход 400 мс).
- Превью при наведении (раскрывающийся список, картинка у пункта меню) ждут, пока курсор остановится: задержка на входе 120–150 мс, на выходе — нет.
- Эффекты наведения — только для точного указателя: `@media (hover: hover) and (pointer: fine)`. На телефоне то же состояние должно быть доступно касанием и с клавиатуры (`:focus-visible`).
- Фокус клавиатуры — видимое кольцо 2 px, без анимации.

## Reduced-motion — обязательный путь

`prefers-reduced-motion: reduce` значит «меньше и мягче», а не «всё выключить»:

- убираем перемещение в пространстве, параллакс, масштаб, полёт камеры, автозапуск видео, бесконечные циклы;
- оставляем смену цвета, прозрачности и состояния, которые несут смысл (нажатие видно как более тёмный тон);
- сцены прокрутки показывают законченный кадр или ряд картинок в обычном потоке страницы;
- в GSAP используй `gsap.matchMedia()` с условием `(prefers-reduced-motion: reduce)`: всё, что создано внутри, откатится само, когда условие сменится.

## Цена для телефона

- Всё, что крутится само дольше 5 с, получает кнопку паузы и останавливается вне экрана и во вкладке в фоне.
- Тяжёлое (canvas, WebGL, видео) монтируется, когда секция подходит к экрану, и размонтируется, когда ушла.
- Ориентир: 60 кадров в секунду на телефоне среднего класса. Ниже 50 — упрощай. Проверяй с замедлением процессора в 4–6 раз в инструментах браузера.
- Сдвиг раскладки (CLS) меньше 0,1: место под картинки, счётчики, меню резервируется заранее.

## Не делать

- Появление каждой секции и каждой карточки при прокрутке «снизу с затуханием» — главная примета шаблонного ИИ-сайта.
- Параллакс на тексте; текст, который двигается с другой скоростью, чем страница.
- Анимацию, которая прячет текст, который человек уже мог бы читать.
- Два самостоятельных движущихся объекта в одном экране.
- Мигание без смысла: мерцающие точки, «блёстки», перебор оттенков, «расшифровка» текста ради эффекта.
- Карусель, которая листается сама; вкладки по таймеру.
- Звук без явного включения человеком.
- Длинный отклик кнопки: долгий отклик ощущается как зависание.

## Проверка

Сними движение дважды — обычно и с включённым reduced-motion (в инструментах браузера: Rendering → Emulate CSS prefers-reduced-motion), на 1280 и 390. Тест удаления: убери анимацию — если никто не заметит, её не было нужно.
