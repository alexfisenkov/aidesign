# Видео → сайт

## Когда читать

- Человек дал ролик и хочет «сайт из видео», «как у Apple», «прокрутка двигает видео», «кадр за кадром».
- Ролика нет, но человек хочет кинематографичный пролёт и готов снять или (с разрешения и суммой) сгенерировать.
- Перед этим файлом — `прокрутка-и-сцены.md` (как устроена сцена) и `видео.md` (кодеки, вес, постер).

## Идея

Видео перестаёт идти по времени и идёт по прокрутке: верх сцены — первый кадр, низ — последний. Над видео — 3–7 текстовых битов, которые появляются в нужных местах ролика. Ниже сцены — обычные секции с текстом и одним действием.

## Неснимаемые правила

1. **Колесо не перехватываем.** Страница прокручивается сама, сцена — длинная секция с липким кадром внутри (`position: sticky`). Готовые решения, которые блокируют страницу и превращают колесо в «виртуальный прогресс», не используем: они ломают клавиатуру, трекпад, инерцию телефона, якоря и читалки экрана.
2. **Первый кадр — постер с первой отрисовки.** Сцена никогда не бывает пустой или чёрной.
3. **Назад = вперёд.** Прокрутка вверх возвращает ровно те же кадры.
4. **Законченный кадр при reduced-motion и без скрипта**: постер или ряд из 3–7 стоп-кадров с текстом битов в обычном потоке страницы.
5. **Факты в тексте битов — только из материала человека.**

## Выбери способ

| Способ | Как | Плюсы | Минусы | Когда |
|---|---|---|---|---|
| **А. Последовательность кадров** | ролик режется на 40–160 картинок, кадр рисуется на `<canvas>` по прогрессу | точно, плавно на любом телефоне, перемотка мгновенная | много файлов и памяти, вес растёт с числом кадров | короткий ролик (до ~15 с), «как у Apple», надёжность важнее веса |
| **Б. Перемотка видео** | один MP4, `video.currentTime` по прогрессу | один лёгкий файл, качество видео | нужна правильная кодировка, телефон тормозит на перемотке тяжёлого файла | ролик подлиннее, есть время настроить |
| **В. Цепочка сцен** | несколько клипов подряд, стык — по последнему кадру предыдущего, короткий кроссфейд | «путешествие» по нескольким местам | дорого сделать (съёмка или генерация), сложно проверять стыки | мир из 3–6 сцен, кинематографичный пролёт |
| **Г. Видео за курсором** | горизонтальное положение мыши перематывает видео первого экрана | игривый, необычный первый экран | только мышь | «навороченный» первый экран; на телефоне — обычный бесшумный цикл |

## А. Последовательность кадров

### Бюджет кадров

| Длина ролика | Кадров (компьютер) | Кадров (телефон) |
|---|---|---|
| до 10 с | 50–60 | 30–40 |
| 10–30 с | 80 | 40–50 |
| 30–60 с | 120 | 60 |
| больше 60 с | 160 — и лучше сократить ролик | 80 |

- Меньше 40 кадров — дёргается; больше 160 — тяжело и не нужно.
- Ширина кадра: компьютер 1280–1600 px, телефон 720–900 px (вертикальный кадр, если ролик позволяет).
- Формат WebP (качество 70–80) или AVIF; 60–150 КБ на кадр.
- Весь набор: компьютер до ~8–12 МБ, телефон до ~3–5 МБ. Больше — меньше кадров или ниже качество.
- Память: раскодированный кадр 1600×900 занимает около 5,5 МБ; 120 таких — уже гигабайт. Поэтому не держи все кадры раскодированными (`ImageBitmap`) одновременно — храни как сжатые картинки и раскодируй ближайшие к текущей позиции.

### Нарезка

```bash
# длина и частота ролика
ffprobe -v error -show_entries format=duration -of csv=p=0 ролик.mp4
# 80 кадров из 20-секундного ролика: fps = 80 / 20 = 4
ffmpeg -i ролик.mp4 -vf "fps=4,scale=1600:-2" -c:v libwebp -quality 75 кадры/f_%04d.webp
# телефон: 40 кадров, вертикальный центр, 720 px
ffmpeg -i ролик.mp4 -vf "fps=2,crop=ih*9/16:ih,scale=720:-2" -c:v libwebp -quality 72 кадры-м/f_%04d.webp
```

### Показ

- Сцена: секция 300–600 % высоты экрана (на телефоне 200–400 %); ориентир — 20–30 px прокрутки на кадр, чтобы ощущение «сколько кручу — столько двигается» не зависело от длины ролика.
- Кадр выбирается как `round(прогресс × (N − 1))`, рисование — один раз за кадр в `requestAnimationFrame` и только если номер сменился.
- Холст рисует по правилу `cover` (как `object-fit: cover`) с учётом `devicePixelRatio` (не больше 2).
- Загрузка постепенная: сначала первый кадр (он же постер), затем каждый 8-й, затем каждый 4-й, затем все. Пока нужного кадра нет — рисуй ближайший загруженный.
- Холст — `aria-hidden="true"`; смысл передаёт текст битов в HTML.

## Б. Перемотка видео

- **Кодировка для перемотки**: маленькая группа кадров (GOP), без звука, `faststart`. Перемотка быстрая только до ключевых кадров, а в обычном ролике ключевой кадр раз в несколько секунд.
  ```bash
  ffmpeg -i ролик.mp4 -an -c:v libx264 -preset slow -crf 20 -pix_fmt yuv420p \
    -g 8 -keyint_min 8 -sc_threshold 0 -movflags +faststart сцена.mp4
  # телефон: 720 px, GOP 4 (перемотка на телефоне дороже)
  ffmpeg -i ролик.mp4 -an -vf "scale=720:-2" -c:v libx264 -preset slow -crf 23 -pix_fmt yuv420p \
    -g 4 -keyint_min 4 -sc_threshold 0 -movflags +faststart сцена-м.mp4
  ```
  Каждый кадр ключевым (all-intra) — только если на слабом телефоне всё ещё рывки: файл раздувается в разы.
- **Перемотка работает только если сервер отдаёт куски файла** (HTTP Range). Многие простые серверы этого не делают — видео «застывает» на первом кадре. Надёжно: скачать ролик целиком через `fetch` и играть из `Blob` (`URL.createObjectURL`) — такой файл перематывается всегда.
- **Объединяй перемотки**: не ставь новый `currentTime`, пока видео ещё ищет предыдущий (слушай `seeked`); всегда перематывай к последней цели. Без этого быстрый бросок пальцем замораживает видео.
- **iPhone**: бесшумное видео, которое ни разу не играло, может не показать кадр после перемотки. Держи постер, пока видео не нарисует первый кадр, и «разбуди» видео при первом касании (`play()` → `pause()`). Атрибуты `muted` и `playsinline` не убирай.
- **Отдельный файл для телефона** — легче и, если можно, вертикальный 9:16, а не обрезка из центра. Обрезку из центра используй только как запасной путь и назови это в отчёте.
- Изменение только высоты окна на телефоне (появилась или пропала адресная строка) не пересчитывает сцену — иначе страница прыгает.

## В. Цепочка сцен

- Каждый следующий клип начинается с **настоящего последнего кадра** предыдущего (вытащи его ffmpeg), а не с похожей картинки — тогда стык не виден.
- На стыке — кроссфейд на несколько процентов прогресса.
- Камера не разворачивается на стыке: «вперёд, потом назад» читается как перемотка. Лучше одно непрерывное движение вперёд.
- Одна модель и одни настройки кодирования на всю цепочку.
- Темп: первая и последняя сцена — длиннее (больше прокрутки, камера «задерживается», пока читается текст), переходные — короче.
- Проверяй стыки снимками прямо до и прямо после каждого стыка: композиция должна совпадать.

## Г. Видео за курсором

- Положение мыши по горизонтали (0…1) → время видео; интерполяция, чтобы не дёргалось; кодировка — как в способе Б.
- Только для точного указателя. На телефоне и при reduced-motion — обычный бесшумный цикл или постер.
- Не на каждой секции — один первый экран.

## Генерация ролика (если своего нет)

- До любой генерации — короткое интервью: бренд и что сцена должна рассказать, арт-направление (материал, свет, настроение), порядок сцен, нужна ли телефонная версия, бюджет.
- Сначала бесплатные пути: своя съёмка на телефон (один непрерывный проход камеры 6–15 с, без склеек, предмет в центре, место под заголовок), наезд по фото.
- Генерация видео нейросетью — **платная**: только по прямому разрешению человека с названной суммой; сначала смета (сколько роликов, сколько стоит) и короткий пробный ролик; для телефонной версии — отдельная вертикальная цепочка (это примерно вдвое дороже — спроси, нужна ли).
- Записывай в отчёт: сервис, модель, запрос, длина, права на результат.
- Перед генерацией — три этюда стиля, которые различаются материалом, светом и композицией, а не только акцентным цветом.

## Текст битов

- 3–7 битов; у каждого заголовок 3–8 слов и одна фраза. Позиция бита — диапазон прогресса, в котором он видим (вход и выход — кроссфейд).
- Текст на спокойной части кадра; контраст проверяй по самому светлому кадру диапазона.
- Первый бит виден сразу при загрузке, последний держит главное действие (кнопку).
- Капс-надзаголовки над каждым битом — нет (это примета шаблона, `../язык/антипаттерны.md`).

## Цена для телефона

Самый тяжёлый приём базы. На телефоне: меньше кадров или лёгкий файл 720p, короче сцена, постер сразу, проверка на замедлении процессора 4–6x и в Safari на iPhone. Если не тянет — телефон получает ряд стоп-кадров с текстом в обычном потоке.

## Проверка

- Прокрутка вперёд, назад, медленно и броском; 390, 768, 1024, 1440.
- Первый кадр виден сразу; нет чёрных и пустых кадров.
- Способ Б: в консоли `video.seekable.end(0) > 0`; `currentTime` идёт за прокруткой.
- Телефону отдаётся лёгкий файл (вкладка «Сеть»).
- Reduced-motion: постер и стоп-кадры, видео не грузится.
- Общий вес сцены записан в отчёт.

## Не делать

- Блокировку страницы и перехват колеса.
- Ролик 50 МБ «потому что все кадры ключевые».
- Пустую сцену до загрузки.
- Шрифтовые и цветовые наборы чужого бренда из исходного скилла — палитру и шрифты берём из направления, выбранного человеком.
- Обещание бесшовности, если стыки не проверены глазами.
