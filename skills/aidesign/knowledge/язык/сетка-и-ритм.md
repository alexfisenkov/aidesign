# Сетка и ритм

## Когда читать

- Перед превью: у трёх вариантов разные **композиции** (это главное различие, не цвет).
- При сборке страницы — всё целиком.
- При редизайне готового сайта — раздел «Проверка».

## Главное

Раскладка переводит приоритет продукта в порядок чтения, группы и ритм. Сначала диагноз — что главное, что вместе, что отдельно, — потом передвижение блоков (Imp).

## Тезис раскладки (до правки)

Назвать:

- главный путь чтения или задачи;
- что принадлежит друг другу и что разделяется;
- какой элемент ведёт, какие поддерживают;
- плотность и ритм интервалов;
- как структура меняется на телефоне, планшете, широком экране.

## Группировка и ритм

- **Близость раньше контейнеров.** Связанное — рядом, несвязанное — разнесено. Рамки и карточки не должны компенсировать слабую близость (гештальт, dembrandt-skills).
- **Ритм — контраст тесного и щедрого.** Внутри группы тесно, между группами щедро; **над заголовком места больше, чем под ним** — заголовок принадлежит тому, что открывает (Imp).
- **Шкала отступов, а не случайные числа.** База 4px даёт полезные промежуточные шаги, которых нет у шкалы только по 8: `4, 8, 12, 16, 24, 32, 48, 64, 96, 128`.
- **Повтор поддерживает узнавание;** ломать его — только когда меняется смысл или приоритет. Разнообразие не цель само по себе.
- **`gap`** для расстояний между соседями вместо внешних отступов у детей.

## Каркас

- **Колонки:** 12 на широком экране, 4–6 на планшете, 1–2 на телефоне; поля по краям 16–24px на телефоне, 32–64px на широком.
- **Ширина содержимого:** контейнер 1200–1360px для страницы; текст — 65–75ch внутри.
- **Равные левый и правый края:** всё садится на линии контейнера или колонок, ничего не торчит в одну сторону, нет горизонтальной прокрутки (Taste).
- **Режим посетителя:** «убедить/впечатлить» — асимметрия и смелые разрывы, если мир их заслужил; «работать/читать» — предсказуемая структура и стабильная плотность (Imp).
- **Один раздел — один-два экрана** на лендинге компании: первый экран — герой целиком, без заглядывающего соседа (Taste). Это ориентир для лендинга, не для документации.

## Первый экран

- Говорит, что это, для кого и где, с одним твёрдым фактом; главное действие — внутри первого экрана (Taste).
- Высота — `min-height: 100svh`, не `height: 100vh` (`антипаттерны.md#vh-hero`).
- Открывать самым характерным для предмета: заголовок, фото, демо, живой элемент. «Большая цифра с подписью» — только если это действительно лучшее (FD).

### Одиннадцать раскладок героя (по мотивам Taste)

Taste раздаёт герой случайно по типу дела и материалу; у нас раскладка — одно из главных различий трёх превью, и выбирается по материалу, который у человека **реально есть**:

| Раскладка | Что это | Когда |
|---|---|---|
| Сплит | текст с одной стороны, картинка с другой | есть одна сильная картинка или интерфейс |
| Фото | фото на весь герой, текст на спокойной части кадра | есть хорошее фото места или работы |
| Продукт | предмет целиком на широкой сцене, крупно | физический продукт, рендер по брифу |
| Редакционный | заголовок и текст как разворот журнала | эксперт, медиа, кейс |
| Коллаж | несколько фото или фрагментов в композиции | много материала разного вида |
| Слово | одно-два слова огромным кеглем | бренд-высказывание, минимализм |
| Фильм | видео или кадр из ролика во весь экран | есть ролик |
| Высказывание | крупная фраза без картинки | сильный текст, нет визуала |
| Триптих | три кадра рядом | три равных стороны дела |
| По центру | заголовок и действие по центру, картинка ниже | простой продукт, одно действие |
| Место | фото места + адрес и часы на первом экране | кафе, студия, магазин |

Правила (Taste): картинка героя заканчивается внутри героя, не обрезается краем первого экрана; на первом экране не больше двух кнопок; странице продукта — только «продукт», «фото», «фильм» (иначе продукт не виден крупно); на телефоне текст первым. Цветное поле вместо работы — не герой.

## Шаблоны страниц

UI UX Pro Max описывает 34 схемы лендингов как порядок разделов. Схема — подсказка, а не каркас: порядок разделов выводится из вопросов человека, который пришёл на страницу (Taste: «форма из вопросов читателя»). Самые ходовые:

| Схема | Порядок | Для чего |
|---|---|---|
| Минимальная одноколоночная | герой → коротко → 3 пользы → действие | услуга, небольшой продукт |
| Демо продукта | герой → живой фрагмент → возможности по разделам → действие | софт |
| Сюжетная | крючок → главы (проблема, путь, решение) → действие | история, кейс, запуск |
| Видео-герой | видео → ключевые возможности → польза → действие | есть сильный ролик |
| Тарифы | ценность → тарифы → сравнение → вопросы → действие | продажа подписки |
| Мероприятие | дата и место → спикеры → программа → регистрация | события |
| Рассылка / контент | ценность + форма → архив → об авторе | авторские медиа |
| Портфолио | имя и роль → работы → подход → контакт | личный сайт |
| Каталог / справочник | поиск → категории → избранное → доверие | маркетплейс |
| До и после | исходное → сравнение → как работает → действие | услуги с видимым результатом |

Отзывы, логотипы клиентов и цифры в любой схеме — только если они есть в брифе (`антипаттерны.md#invented-facts`).

## Плотность

Плотность следует из частоты использования и сложности решения: панель для аналитика плотнее лендинга кофейни. Шкала: `компактно (0.75) · обычно (1) · просторно (1.25)` множителем к шкале отступов.

## Адаптивность

- Перестраивать структуру, а не сжимать: перестановка, сворачивание, перенос, показ по запросу.
- Ширины проверки: 320, 390, 768, 1024, 1280, 1440 (UUPM, Taste).
- На телефоне: одна колонка, сплиты — текст сверху, кнопки во всю ширину, меню на весь экран.
- Касание: цели от 44×44px, между целями от 8px (UUPM); для веба минимум WCAG — 24×24px.
- Вырезы экрана: `env(safe-area-inset-*)` у полноэкранных раскладок (WIG).
- Длинное содержимое: `min-width: 0` у детей flex, `overflow-wrap: anywhere` для длинных слов и ссылок, обрезка с возможностью раскрыть (WIG, UUPM).
- Компоненты, которые встречаются в разных местах, — через container queries.
- Порядок фокуса и диктора совпадает с видимым порядком.

## Глубина и поверхности

- Глубина — только когда проясняет состояние или иерархию.
- Подъём объявлять одним способом: граница **или** тень (`антипаттерны.md#ghost-card`).
- Не глубже двух вложенных коробок (`антипаттерны.md#nested-cards`).
- Шкала слоёв: 10 — выпадающие, 20 — липкая шапка, 30 — оверлей, 50 — модальное окно, в переменных (`антипаттерны.md#z-index-chaos`).

## Проверка

- **Тест прищура:** размыть страницу — видно ли главное, второстепенное и основные группы по порядку?
- Путь чтения ясен на всех ширинах; длинный текст, пустые состояния, масштаб и перевод не ломают структуру.
- Нет горизонтальной прокрутки на 320.
- `check.py`: `vh-hero`, `z-index-chaos`, `icon-tile-cards`, `numbered-markers` — без находок.

## Не делать

- Сетку одинаковых карточек как каркас страницы (`антипаттерны.md#card-grid`).
- Один и тот же отступ везде (`антипаттерны.md#monotonous-spacing`).
- Шаблон раздела «надзаголовок → заголовок → лид → три карточки» на каждом экране (`антипаттерны.md#section-template`).
- Пиксельное позиционирование вместо потока; измерение раскладки скриптом там, где справится grid/flex.
