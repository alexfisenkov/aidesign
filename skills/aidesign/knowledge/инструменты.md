# Инструменты: готовые рецепты

## Когда читать

Программы стоят (`setup.py doctor` показал «есть»), и нужно ими воспользоваться: снять страницу на 390 и 1280, сжать видео для первого экрана, перевести фото в WebP или AVIF, прогнать Lighthouse. Как поставить недостающее — не здесь, а `python3 .aidesign-work/setup.py plan <имя>` (`phases/0-start.md`).

Оснащение AI Design — только программы на компьютере (Python, git, Node.js, Chromium через Playwright, ffmpeg) и Figma MCP по желанию. Браузер для проверки — Playwright из командной строки, отдельный MCP браузера не нужен. Другие MCP и скиллы не ставятся.

## 1. Локальный сервер

Страницу снимают и проверяют **по http**, не по `file://`: шрифты, модули JS и видео по `file://` ведут себя иначе.

```bash
python3 .aidesign-work/ad.py --serve-http 8000 --directory <папка сайта>   # адрес http://127.0.0.1:8000/
```

Это сервер AI Design с Range (файлы кусками): без Range видео по прокрутке не перематывается и стоит на первом кадре, поэтому встроенный `http.server` Python не годится. У проекта на фреймворке — его команда (`npm run dev`, `npm run preview`) и её адрес. Сервер запускай в фоне и гаси, когда снял.

## 2. Снимки 390 и 1280 (Playwright)

```bash
npx -y playwright screenshot --viewport-size=390,844 --full-page --wait-for-timeout=800 \
  http://127.0.0.1:8000/ shot-390.png
npx -y playwright screenshot --viewport-size=1280,800 --full-page --wait-for-timeout=800 \
  http://127.0.0.1:8000/ shot-1280.png
```

- Снимки кладутся в папку прогона: `.aidesign-work/<dir>/shots/<страница>-390.png`, `…-1280.png`. В папку сайта — никогда.
- `--wait-for-timeout` даёт анимациям появления доиграть; страница с долгим входом — 1500–2000.
- Тёмная тема — `--color-scheme=dark`. Только первый экран — без `--full-page`.
- Ошибка «Executable doesn't exist» — браузер не скачан: `npx playwright install chromium` (на Linux ещё `install-deps`, она просит пароль — команду человеку). Это же `setup.py install playwright --yes`.
- Сайт из нескольких страниц — по паре снимков на каждую страницу из `pages/`.

Что смотреть на снимках — `phases/5-check.md`. Снимок не заменяет проверку касанием, фокусом и «уменьшить движение»: их делает браузер агента или человек на телефоне.

## 3. Видео для первого экрана (ffmpeg)

Цель — без звука, MP4 H.264 для всех и WebM для тех, кому легче, постер, ориентир веса: **до 2–3 МБ на компьютер, до 1–1,5 МБ на телефон** для 8–12 секунд.

```bash
# MP4 H.264 — для всех браузеров
ffmpeg -i исходник.mov -an -vf "scale=1280:-2,fps=30" -c:v libx264 -preset slow -crf 26 \
  -pix_fmt yuv420p -movflags +faststart assets/video/hero-1280.mp4
# WebM VP9 — легче при том же виде
ffmpeg -i исходник.mov -an -vf "scale=1280:-2,fps=30" -c:v libvpx-vp9 -crf 36 -b:v 0 \
  -row-mt 1 assets/video/hero-1280.webm
# Вертикальная версия для телефона
ffmpeg -i исходник.mov -an -vf "crop=ih*9/16:ih,scale=720:-2,fps=30" -c:v libx264 -preset slow -crf 27 \
  -pix_fmt yuv420p -movflags +faststart assets/video/hero-720v.mp4
# Постер — первый кадр (он же показывается при «уменьшить движение»)
ffmpeg -ss 0 -i assets/video/hero-1280.mp4 -frames:v 1 -q:v 3 assets/video/hero-poster.jpg
```

- Вес вышел больше ориентира — подними `-crf` на 2 и повтори; качество смотри глазами, а не по цифре.
- `-an` убирает звук: фоновое видео со звуком не автозапускается.
- Разметка, автозапуск, reduced-motion, AV1 — `движение-и-медиа/видео.md`; ролик в сайт по кадрам — `движение-и-медиа/видео-в-сайт.md`.

## 4. Кадры из ролика

```bash
ffmpeg -i ролик.mp4 -vf "fps=1,scale=1600:-2" -q:v 3 кадры/k_%03d.jpg       # кадр в секунду
ffmpeg -ss 00:00:07.5 -i ролик.mp4 -frames:v 1 -q:v 2 кадр-7.5с.jpg           # один кадр по времени
```

## 5. Фото в WebP и AVIF

```bash
ffmpeg -i фото.jpg -vf "scale=1600:-2" -c:v libwebp -quality 78 assets/img/фото-1600.webp
ffmpeg -i фото.jpg -vf "scale=800:-2"  -c:v libwebp -quality 76 assets/img/фото-800.webp
ffmpeg -i фото.jpg -vf "scale=1600:-2" -c:v libaom-av1 -still-picture 1 -crf 32 assets/img/фото-1600.avif
```

- Две ширины (800 и 1600) — для `srcset`; у `<img>` всегда `width`, `height` и `alt`.
- «Unknown encoder 'libaom-av1'» — ffmpeg собран без AV1: оставь WebP, этого хватает.
- Обработка, кадрирование и права на фото — `движение-и-медиа/фото.md`. Исходники человека не перезаписывай: новые файлы рядом, в `assets/img/`.

## 6. Lighthouse — только по пути

Не ставится отдельно. Если на компьютере есть Chrome или Chromium и Node.js:

```bash
npx -y lighthouse http://127.0.0.1:8000/ --only-categories=performance,accessibility,best-practices \
  --form-factor=mobile --output=html \
  --output-path=.aidesign-work/<dir>/lighthouse.html --chrome-flags="--headless=new"
```

Не нашёл Chrome — пропусти молча, одной строкой в отчёте «Lighthouse не запускался: нет Chrome». Цифры Lighthouse — подсказка, а не приговор: блокирующее — то, что видно на снимках и в `phases/5-check.md`.

## 7. Сбой команды

Команда упала — человеку код выхода и последние строки вывода, без кода целиком, и три пути: «повторить (а), поставлю сам (б), пропустить (в)». Ничего не удаляется. Пропущено — проверка идёт без этого инструмента, и отчёт это называет.

## Не делать

- Не снимать по `file://` и не класть снимки в папку сайта.
- Не скачивать программы с посторонних сайтов: только `setup.py` и официальные установщики.
- Не просить пароль в чат: команда с `sudo` или правами администратора — человеку в его Терминал.
- Не перезаписывать исходные фото и видео человека.
