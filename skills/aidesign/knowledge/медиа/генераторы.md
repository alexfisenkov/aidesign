# Генераторы: распознать, подключить, генерировать в бюджете

## Когда читать

- Подготовка: узнать, какие генераторы картинок, видео, звука и 3D подключены у человека.
- Интервью, тема «Медиа»: человек выбрал «генерировать» или «вперемешку».
- Сборка: план медиа готов, начинается первая платная генерация.
- Что-то пошло не так: нет баланса, задача висит, ссылка не скачивается.

Каталог сервисов (имена инструментов, команды подключения, ссылки на документацию) — `генераторы.json` в этой папке; его читает `tools/media.py`, руками его не правят.

## 1. Распознать, что подключено

1. Собери список имён своих инструментов (MCP вида `mcp__<сервер>__<инструмент>` и встроенные, например `image_gen` у Codex) в файл, по имени в строке.
2. `python3 .aidesign-work/media.py detect --tools-file <файл> --json` — вернёт найденные сервисы: что умеют (картинки, видео, звук, 3D, вектор, SVG), какими инструментами смотреть баланс, цену, ждать и скачивать. Незнакомый сервер с «image», «video», «generate» в именах инструментов тоже попадёт — как «общий».
3. Запиши найденное в учёт: `python3 .aidesign-work/ad.py media connected --ids <id через запятую>`.
4. Покажи человеку таблицу простыми словами:

| Подключено | Что умеет | Баланс |
|---|---|---|
| Higgsfield | картинки, видео, 3D | 1 240 кредитов |
| Встроенная генерация Codex | картинки | в рамках подписки |

Баланс — только если у сервиса есть инструмент баланса и он ответил; не угадывай.

Почему так: агент не должен обещать генерацию, которой нет, и не должен молча тратить деньги сервиса, о котором человек забыл.

## 2. Подключить нужный

- Человек хочет сервис, которого нет: `python3 .aidesign-work/media.py connect <id> --host claude|codex` печатает официальную команду подключения под его среду. Выполняешь её **только после «да»**; вход в аккаунт (OAuth, ключ, логин) человек делает сам — ключи в чат не просим и не пишем в файлы.
- После подключения часто нужен перезапуск среды — скажи об этом прямо.
- Сервиса нет в каталоге — общий шаблон из `connect` и ссылка на его официальную документацию; ничего не выдумывать.

## 3. Бюджет — один вопрос на прогон

Перед первой платной генерацией один вопрос: «На картинки и видео тратим до N <кредитов сервиса / рублей>?» Ответ:
```bash
python3 .aidesign-work/ad.py media budget --limit N --unit <кредиты|руб>
```
- Внутри суммы генерируешь без вопросов; после каждой генерации — `ad.py media spend --service <id> --amount <сколько> --item "<место>"`; панель показывает «потрачено X из N».
- Перед генерацией: `ad.py media check --amount <цена>` — код 1 значит «выйдет за сумму» (или бюджета нет): новый вопрос человеку с суммой.
- Сервис не называет цену заранее — скажи это человеку. Сервис принимает потолок (например, `max_credits`) — поставь его не выше остатка бюджета и считай по факту из ответа.
- **Цена неизвестна и потолок не принимается — вслепую не генерируй никогда.** Два пути:
  1. проверь по остатку бюджета оценкой сверху: `ad.py media check --amount <оценка>`, где оценка — самой дорогой известной цене этой модели у этого сервиса (из инструмента цены, каталога моделей сервиса или его страницы цен, а не по памяти); код 0 — генерируй, после — `ad.py media spend` с фактической суммой;
  2. оценки сверху нет или она не влезает в остаток — сначала спроси человека с `ad.py ask action`: «Цену заранее сервис не называет; самая дорогая известная — около N. Генерируем?»
- Бесплатное (код, свои фото, бесплатные квоты, о которых сказал сам сервис) — без бюджета.

## 4. Инструкции — до промпта

Порядок, по которому пишется промпт под конкретную модель:
1. **Инструкции самого сервера.** Многие MCP отдают свои правила (как называть модели, как прикреплять файлы, что обязательно перед генерацией) — прочитай их до первой задачи.
2. **Установленный скилл под эту модель.** `python3 .aidesign-work/media.py skills` перечисляет скиллы и инструкции человека про промпты и медиа; есть aimaster — по [aimaster.md](aimaster.md) возьми файл под модель.
3. **Эта папка:** [промпты-картинки.md](промпты-картинки.md), [промпты-видео.md](промпты-видео.md), [кино-язык.md](кино-язык.md), [по-референсам.md](по-референсам.md), [вектор-3d-звук.md](вектор-3d-звук.md).

Что прочитано — строкой в `media-plan.md` («Seedance 2.5: инструкция сервера + aimaster current/seedance-2-5.md»).

## 5. Выбрать модель под место

1. Для каждого места из плана запиши жёсткие требования: создание или правка, есть ли референс товара или человека и сколько их, пропорция, длительность, нужен ли начальный и конечный кадр (петля), нужен ли беззвучный файл.
2. Посмотри **текущий** каталог моделей сервиса (а не по памяти и не прошлой сессии) и отбрось модели, которые хоть одно требование не держат. Новая версия, известное имя и цена — не доказательство, что модель подходит.
3. Из подходящих выбери и запиши причину одной строкой. Если не подходит ни одна — назови конфликт и предложи изменение (короче ролик, другой путь референса, другой сервис); молча ничего не урезай.
4. «Без звука» в настройках не гарантирует беззвучный файл — после скачивания звук всё равно убирается при подготовке.

## 6. Общий цикл одной генерации

`баланс → цена → проверка бюджета → задача → ожидание → скачать в проект → посмотреть глазами → подготовить под сайт → записать в опись`

1. **Баланс и цена** — инструментами сервиса, если они есть.
2. **`ad.py media check`** — укладываемся ли.
3. **Задача** — промпт по правилам модели; референсы — с ролями, теги — только выданные сервисом ([по-референсам.md](по-референсам.md)).
4. **Ожидание** — инструментом ожидания сервиса; не плодить повторные задачи, пока первая не ответила.
5. **Скачать сразу:** `python3 .aidesign-work/media.py fetch --url <ссылка> --out assets/raw/<имя>` — ссылки сервисов временные; тип файла проверяется по первым байтам, лишнее не скачивается.
6. **Посмотреть глазами** — картинку в полный размер ([качество-фото.md](качество-фото.md)), видео целиком и покадрово. Не годится — одна правка, не больше двух перегенераций одного места без вопроса человеку.
7. **Подготовить:** `media.py prep image --in <файл> --out assets/img` (WebP и AVIF нескольких ширин) или `media.py prep video --in <файл> --out assets/video` (MP4 H.264 без звука, WebM, постер); для видео по прокрутке — рецепт из [промпты-видео.md](промпты-видео.md).
8. **Записать:** `media.py record --slot <место> --file <файл> --source <id сервиса> --prompt "<промпт>" --alt "<описание>"` и `ad.py media spend …`.

Генерирует **ведущий агент**, не субагенты: один счётчик бюджета и одна опись. Субагенту можно отдать подготовку файлов и вёрстку.

## 7. Сбои

| Что видишь | Что делать |
|---|---|
| нет баланса или не хватает | остановиться, сказать человеку сумму, предложить другой подключённый сервис, код или плашку |
| задача висит дольше обычного | подождать инструментом ожидания ещё раз; новую задачу не ставить, пока старая не закончилась или не упала — иначе двойное списание |
| сервис отказал по правилам содержания | переформулировать нейтрально (без имён людей, брендов, оружия); не обходить запрет |
| ссылка не скачивается | ссылка истекла — получить свежую инструментом скачивания сервиса; не генерировать заново |
| `fetch` ответил «неизвестный тип» | сервис отдал страницу, а не файл: найти прямую ссылку на файл |
| вход слетел (401, «нужна авторизация») | попросить человека войти заново; самому не вводить данные |
| нет ffmpeg для подготовки | `python3 .aidesign-work/setup.py plan ffmpeg` — команда установки, ставить с «да» |

## Не делать

- Обещать генерацию по сервису, который не найден `detect`.
- Тратить сверх названной суммы без нового «да» с суммой.
- Генерировать при неизвестной цене без потолка и без оценки сверху — «посмотрим, сколько спишут».
- Генерировать субагентами параллельно — сбивается счёт.
- Оставлять в проекте ссылки сервисов вместо файлов.
- Ставить на страницу результат, который никто не открыл глазами.
- Писать ключи и токены в файлы, команды и отчёты.
