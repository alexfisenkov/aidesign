# Промпты видео для сайта: петля героя, бесшовность, прокрутка

## Когда читать

- На странице есть видео: фон первого экрана (петля), видео героя, видео по прокрутке, короткий ролик-доказательство.
- Своего видео нет, а генератор видео подключён и бюджет назван ([генераторы.md](генераторы.md)).
- Превью с приёмом «видео» — материал главного приёма делается **до** превью (раздел «Видео для превью»).

Где видео уместно, разметка, кодеки, вес — [../движение-и-медиа/видео.md](../движение-и-медиа/видео.md). Сцена из ролика по прокрутке — [../движение-и-медиа/видео-в-сайт.md](../движение-и-медиа/видео-в-сайт.md). Камера и свет словами — [кино-язык.md](кино-язык.md).

## Чем видео для сайта отличается от ролика

1. **Это не история, а состояние.** Фон героя — одно спокойное движение (пар над чашкой, свет ползёт по стене, ткань колышется), без сюжета, монтажа и героя, который «что-то делает». Почему: посетитель смотрит на заголовок, а видео за ним — настроение; событие в фоне отвлекает и плохо зацикливается.
2. **Без звука.** Фоновое видео всегда беззвучное; даже если модель делает звук, его выключают при подготовке (`-an`). Почему: автозапуск со звуком браузеры блокируют, а люди закрывают вкладку.
3. **Место под текст заложено в кадре.** Как у картинки: где заголовок, там спокойная зона без движения и мелких деталей.
4. **Коротко.** 4–8 секунд на петлю, один шот. Почему: длиннее — тяжелее файл и больше шансов на артефакт; петля всё равно повторяется.
5. **Первый кадр — постер.** Он виден до загрузки и при reduced-motion, поэтому сам по себе должен быть хорошей фотографией.

## Общая формула промпта

`Назначение → объект → окружение → действие (одно, с конечной точкой) → камера (тип и одно движение) → свет → фактура → чем заканчивается`.

- **Видео из картинки (image-to-video) — главный путь для сайта.** Сначала делается и утверждается кадр (это и постер), потом он оживляется. В промпте — **только движение и изменения**, не описание того, что уже видно: «пар медленно поднимается и рассеивается, свет из окна чуть теплеет, камера неподвижна». Почему: описание кадра заново заставляет модель его перерисовать — предмет «плывёт».
- **Одно движение камеры за шот:** «static tripod», «slow dolly in», «slow pan left». Без «камера движется ближе» — называй тип. Почему: несколько движений сразу дают дрожь и деформации.
- **Действие с концом:** «takes a sip and lowers the cup», а не «drinks coffee». Почему: модель понимает, чем закончить, и не обрывает на середине.
- **Конкретный свет:** «warm window light from the left», а не «dramatic lighting».
- **Настройки — не в промпт.** Длительность, пропорция, разрешение, «HQ», режим (T2V, I2V) — полями сервиса. В Kling секунды словами («0–3 с: …») не пишут вовсе.
- **Без звуковых указаний** для фона; для ролика со звуком — отдельная строка «звук: …» (речь, среда, тишина).

## Петля героя без склейки

Цель — видео, которое крутится по кругу без заметного шва.

1. **Выбери движение, которое замыкается само:** пар, дым, вода, листья на ветру, блики, ткань, медленный свет. Не годится: шаг человека, проезд машины, движение камеры вперёд (в конце камера в другом месте — шов неизбежен).
2. **Камера неподвижна** (`static tripod, locked-off shot`) или почти (очень медленный параллакс, который можно отыграть назад).
3. **Первый и последний кадр одинаковые.** Если сервис принимает начальный и конечный кадр (Kling — Start/End Frame, Veo — first/last frame), дай **одну и ту же** утверждённую картинку на оба места и опиши движение «между»: «steam rises and drifts, the light flickers softly, the scene returns to its initial state». Это самый надёжный способ.
4. **Не принимает конечный кадр** — сгенерируй на 1–2 секунды длиннее нужного и замкни при подготовке: кроссфейд хвоста на начало 0,3–0,5 с (рецепт ffmpeg в [../движение-и-медиа/видео.md](../движение-и-медиа/видео.md), «Кодирование») или «туда-обратно» (ping-pong) — только для движения без направления (пар, вода); идущий назад человек выглядит странно.
5. **Проверь шов:** посмотри 3–4 круга подряд; стоп-кадр последнего и первого кадра рядом — совпадают свет, положение предметов, цвет.

Пример (фон кофейни, image-to-video по утверждённому кадру, начальный и конечный кадр — он же):
```text
Steam rises slowly from the pour-over and drifts to the right, thin and soft. Morning light on the plaster wall warms very slightly and settles back. A faint dust shimmer moves through the window light. Static tripod, locked-off shot, no camera movement. Everything returns to the initial state at the end. Calm, realistic, no new objects.
```

## Бесшовная цепочка сцен (для прокрутки и длинного героя)

- Каждый следующий клип начинается с **настоящего последнего кадра** предыдущего (вытащи его ffmpeg из готового файла), а не с похожей картинки.
- Камера не разворачивается на стыке; одно непрерывное движение вперёд.
- Одна модель и одни настройки на всю цепочку; персонаж и предметы описываются одними и теми же словами во всех промптах.
- Подробности и проверка стыков — [../движение-и-медиа/видео-в-сайт.md](../движение-и-медиа/видео-в-сайт.md), «Цепочка сцен».

## Видео по прокрутке: один лёгкий файл

Проверено на живом прогоне 19.11.2026: для покадровой прокрутки нужен **один** лёгкий файл 720p, в котором ключевой кадр стоит часто, а показывается он **прямо через `<video src>`**. Так видео работает и по `http`, и при открытии страницы как файла (`file://`). Загрузка через `fetch` → `Blob` при открытии как файл не работает (браузер не даёт `fetch` читать файлы с диска), и превью молча остаётся без видео.

Подготовка (беззвучно, 720p — 1280 по ширине, ключевой кадр каждые 4 кадра, заголовок файла в начале):
```bash
ffmpeg -i исходник.mp4 -an -vf "scale=1280:-2" -c:v libx264 -preset slow -crf 24 -pix_fmt yuv420p \
  -g 4 -keyint_min 4 -sc_threshold 0 -movflags +faststart scrub-720.mp4
ffmpeg -ss 0 -i scrub-720.mp4 -frames:v 1 -q:v 3 scrub-poster.jpg
```
(для вертикального кадра — `scale=720:-2`). Ориентир веса — 2–6 МБ на 6–10 секунд. Чаще ключевые кадры (`-g 2` или каждый кадр ключевой) — только если перемотка всё ещё рвётся на слабом телефоне: файл растёт в разы.

Показ — рабочий рецепт (сцена прокрутки, видео прилипает к экрану, время видео следует за прокруткой; при reduced-motion — только постер и текст):
```html
<!doctype html>
<html lang="ru">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Видео по прокрутке</title>
<style>
  body { margin: 0; background: #191714; color: #f4efe7; font: 1.0625rem/1.55 Georgia, serif; }
  .scrub { position: relative; height: 300svh; }
  .scrub .stage { position: sticky; top: 0; height: 100svh; overflow: hidden; }
  .scrub video { width: 100%; height: 100%; object-fit: cover; display: block; }
  .scrub h2 { position: absolute; left: 6vw; bottom: 8vh; margin: 0; max-width: 18ch; font-size: clamp(1.8rem, 4vw, 3.2rem); line-height: 1.1; }
  .after { padding: 10vh 6vw; max-width: 60ch; }
  @media (prefers-reduced-motion: reduce) {
    .scrub { height: auto; }
    .scrub .stage { position: relative; height: 70svh; }
  }
</style>
</head>
<body>
<section class="scrub">
  <div class="stage">
    <video src="scrub-720.mp4" poster="scrub-poster.jpg" muted playsinline preload="auto" aria-hidden="true"></video>
    <h2>Как рождается чашка</h2>
  </div>
</section>
<p class="after">Дальше — обычный текст страницы.</p>
<script>
(() => {
  const scene = document.querySelector('.scrub');
  const video = scene.querySelector('video');
  if (matchMedia('(prefers-reduced-motion: reduce)').matches) { video.preload = 'none'; return; }
  let target = 0, seeking = false, ticking = false;

  function progress() {
    const r = scene.getBoundingClientRect();
    const run = r.height - innerHeight;
    return run > 0 ? Math.min(1, Math.max(0, -r.top / run)) : 0;
  }
  function seek() {
    if (!video.duration || seeking) return;
    const t = target * (video.duration - 0.05);
    if (Math.abs(video.currentTime - t) < 0.01) return;
    seeking = true;
    video.currentTime = t;
  }
  video.addEventListener('seeked', () => { seeking = false; seek(); });
  video.addEventListener('loadedmetadata', () => { target = progress(); seek(); });
  addEventListener('scroll', () => {
    if (ticking) return;
    ticking = true;
    requestAnimationFrame(() => { ticking = false; target = progress(); seek(); });
  }, { passive: true });
  addEventListener('pointerdown', () => { video.play().then(() => video.pause()).catch(() => {}); }, { once: true });
})();
</script>
</body>
</html>
```

Что здесь важно: колесо не перехватывается (обычная прокрутка, видео лишь следует); новая перемотка не ставится, пока видео ищет предыдущую (`seeked`) — иначе быстрый бросок пальцем замораживает кадр; первое касание «будит» видео на iPhone; `muted` и `playsinline` не убирать.

По http перемотка работает, только если сервер отдаёт файл кусками (HTTP Range, ответ 206). Встроенный сервер Python (`http.server`) кусками не отдаёт: видео застывает на первом кадре. Локально показывай и проверяй сервером AI Design с Range — `python3 .aidesign-work/ad.py --serve-http 8000 --directory <папка сайта>`, адрес `http://localhost:8000/`; на хостинге и в nginx куски включены сами. `fetch` → `Blob` допустим лишь как улучшение поверх рабочего `<video src>`, когда чужой сервер без Range не поменять, и только по `http`, с возвратом к прямому `src`, если `fetch` упал.

## Видео для превью

- Если главный приём варианта — видео (фон, прокрутка), материал делается **до** превью: свой ролик человека или сгенерированный в пределах бюджета. Один общий лёгкий файл 720p на все три превью; превью отличаются подачей поверх (шрифт, раскладка, цвет плашек, темп текста), а не тремя разными роликами.
- CSS-намёк вместо видео — только если материала нет и получить нельзя; тогда человеку прямо: «видео в превью нет, потому что …».
- Перед показом проверь в браузере по `http`: `video.readyState >= 2`, при прокрутке `currentTime` меняется.

## По моделям

Модели и их возможности меняются; перед запуском сверяй текущую схему операции сервиса (длительность, пропорции, начальный и конечный кадр, референсы, звук) и цену.

### Seedance (ByteDance)

Сверено по [анонсу Seedance 2.5 от 31.07.2026](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5) и материалам 2.0 (по инструкции владельца): видео со звуком, продолжение клипов, референсы картинками, видео и звуком.

- Формула: `замысел → объект → окружение → действие → камера → свет и тень → фактура → звук → стиль → чем заканчивается`.
- Конкретика вместо громких слов: «slow lateral dolly», «wet asphalt reflections», «controlled deceleration into macro close-up» — а не «epic, cinematic».
- Правка — только запрошенное: «сохрани сцену, поменяй свет на вечерний», без переписывания всего промпта.
- Короткому клипу — мало событий: 5–8 секунд — до 3–5 шотов, для фона сайта — один.
- У агрегаторов (Magnific, Higgsfield, Syntx) способ прикрепить референсы свой; в Magnific визуальные референсы и начальный/конечный кадр не сочетаются.

### Kling (Kuaishou)

Сверено по [сообщению о запуске Kling 4.0 от 15.10.2026](https://ir.kuaishou.com/news-releases/news-release-details/kling-ai-officially-launches-next-generation-kling-40-raising/) и инструкции к 3.0 (по инструкции владельца).

- Формула: `сцена → персонажи → действие по порядку → камера → звук → стиль`. Коротко: длинные промпты Kling понимает хуже.
- Image-to-video: картинка показывает «что», промпт — «как двигается»; тип кадра и внешность не описывать.
- Начальный + конечный кадр (F2F): описывай процесс перехода и что неизменно — «композиция не меняется, камера неподвижна». Это главный инструмент бесшовной петли.
- Отрицательного промпта в 3.0 нет; секунды, разрешение, «Realistic style» — только в интерфейсе.
- Один и тот же предмет или человек — одинаковыми словами во всём промпте.

### Veo (Google)

Сверено 05.11.2026 по [документации Gemini API для Veo](https://ai.google.dev/gemini-api/docs/veo) (по инструкции владельца): семейство Veo 3.1; во Flow и приложении Gemini операции могут отличаться от API.

- Тип кадра, одно движение камеры, действие с конечной точкой; промпт на английском, не длиннее ~2000 знаков.
- Звук Veo делает сам — для фона сайта он не нужен, а при подготовке выключается.
- Если модель добавила субтитры — повтори запрет на них дважды; лучше — снова без текста в кадре.
- Image-to-video и первый/последний кадр — только движение, без перерисовки кадра.

### Runway

Сверено 19.11.2026 по официальному [руководству Image to Video](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide) (написано под Gen-4.5; содержание сверено по выдержкам поиска, страница не открылась целиком): в image-to-video описывается движение объекта и камеры, а не сама картинка; начинать с простой фразы движения и добавлять детали постепенно.

## После генерации

Скачай файл в проект сразу, посмотри целиком и покадрово (руки, предметы, свет, шов петли), выключи звук и подготовь форматы: `media.py prep video` (MP4 H.264 + WebM + постер; для прокрутки — рецепт выше), запиши в опись медиа ([генераторы.md](генераторы.md)).

## Не делать

- Сюжет, монтаж и звук в фоновом видео.
- Движение камеры вперёд в петле (шов неизбежен).
- Описывать заново кадр, который уже дан картинкой.
- Секунды, разрешение и режим словами в промпте.
- Показывать видео по прокрутке только через `fetch` → `Blob`: по `file://` оно не загрузится.
- Ставить новую перемотку, пока видео ещё ищет предыдущую.
- Три разных тяжёлых ролика на три превью вместо одного общего лёгкого файла.
- Заменять видео в превью CSS-намёком, если материал есть.
