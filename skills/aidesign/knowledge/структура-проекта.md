# Структура проекта: где что лежит

## Когда читать

На Подготовке, когда `scaffold.py plan` показал, чего не хватает; на Сборке, когда новый файл ищет себе место или человек согласился разложить готовый сайт; при записи блока `aidesign` — раздел «Схема» называет пути, на которые он ссылается.

## Схема

Её создаёт `python3 .aidesign-work/scaffold.py apply --root . --kind page|site --title "…"`. `page` — одна страница (лендинг, блок, презентация), `site` — несколько страниц: то же плюс `pages/`. Сначала одна страница, потом выросла — `apply --kind site` дописывает только `pages/`.

```
index.html                 главная страница
pages/                     остальные страницы (только site): pages/about.html, pages/prices.html
assets/css/                стили сайта — значения только через var(--…) из design-system/
assets/js/                 скрипты
assets/img/                картинки WebP/AVIF, по две ширины, с width и height
assets/video/              видео MP4 H.264 + WebM, постер
assets/fonts/              свои шрифты (свободные, с лицензией рядом)
design-system/             единственный источник стиля
  tokens.css               источник: :root { --color-… --font-… --space-… --radius-… --shadow-… --motion-… }
  tokens.json              выводится из tokens.css командой designsystem.py export — руками не правится
  styleguide.html          витрина: цвета, шрифты, отступы, кнопки, карточки, формы, разделы
  README.md                как подключить человеку и агенту
  CHANGELOG.md             дата — что изменилось — почему
DESIGN.md                  правила дизайна словами и токенами — для любого агента
AGENTS.md                  память проекта; в конце блок <!-- aidesign:start --> … <!-- aidesign:end -->
CLAUDE.md                  одна строка @AGENTS.md (если своего текста нет)
README.md                  что за проект и как открыть
.gitignore                 .aidesign-work/, node_modules/, .env, .DS_Store — мимо git
.aidesign-work/            рабочая папка AI Design: панель, прогоны, инструменты, backups/ — не в git
CONTEXT.md, docs/adr/      слова дизайна и почему выбрано направление (пишет Передача)
```

Почему так: человек находит файл по смыслу папки, агент — по блоку `aidesign`; стиль в одном месте, поэтому смена цвета — одна строка в `tokens.css`, а не поиск по всему сайту.

## Пустая папка или «свалка»

- **Пустая** (или только `референсы/`) — `apply` сразу, без вопроса, и одна строка человеку: «Разложил проект: страница, стили, дизайн-система, правила для агентов».
- **Плоская свалка** (картинки, тексты, заметки вперемешку, но не сайт) — сначала бэкап «до» (`backup.py create`), потом `apply`; свои файлы человека не перекладываются молча: предложи списком «`фото1.jpg` → `assets/img/`», перенос — после «да».
- **Нет git** и git установлен — `apply --git`: `git init` и коммит «До AI Design» до любых правок; человеку одной строкой. Git не знает имени (`user.name`, `user.email`) — не выдумывай их: скажи человеку, что история начнётся после `git config --global user.name "…"` и `user.email`, и работай дальше без коммита — бэкапы всё равно есть.

## Готовый сайт

Работающий сайт **не перекладывается без согласия**: адреса страниц, ссылки и пути к картинкам — часть того, что работает. `scaffold.py plan` на готовом сайте помечает раскладку (`index.html`, `assets/`, `pages/`) как `propose` — только показать.

1. Чего не хватает и не ломает ничего (`design-system/`, `DESIGN.md`, блок в памяти, строки `.gitignore`) — создаётся после бэкапа «до», без отдельного вопроса.
2. Раскладку меняем только по «да» (`ad.py ask action`): что куда переедет, какие адреса изменятся.
3. После «да» — бэкап, перенос, правка всех ссылок (`href`, `src`, `url(…)` в CSS, импорты JS), затем проверка: каждая страница открывается через локальный сервер, нет 404 на картинки, стили и скрипты (консоль браузера или `npx playwright screenshot` по каждой странице — `инструменты.md`).
4. Адрес страницы, на который могут вести внешние ссылки, сменился — скажи человеку, что старые ссылки перестанут работать, до переноса, а не после.

Проект на фреймворке (`package.json`, `src/`, `app/`) — его раскладка главнее этой схемы: `design-system/` ложится рядом, стили фреймворка подключают `design-system/tokens.css`.

## Не делать

- Не перекладывать работающий сайт без «да» и без бэкапа.
- Не удалять «лишние» файлы: ненужное — только с согласия и переносом, не в корзину.
- Не держать значения цвета и шрифтов в `assets/css/` мимо `design-system/tokens.css`.
- Не коммитить `.aidesign-work/`: там бэкапы и панель, они большие и личные.
