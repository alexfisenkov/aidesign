# Сборка — доводка выбранного варианта до готового сайта

`ad.py stage build`. Этап начинается **только после явного выбора**: в `state.js` у последнего круга `chosen` — буква, а не `none`, и есть `direction`. Нет выбора — вернись в `phases/3-previews.md`; без выбора не собирается ни один раздел.

**Сборка — это доводка, а не пересборка.** Человек выбрал вариант, который видел живым. Его файл превью — основа страницы: **тот же код**, тот же главный приём, тот же материал; к нему достраиваются все разделы, тексты дописываются вместе с человеком, медиа — по плану, и круги правок идут по живой странице, пока человек не скажет «готово». Собрать «в том же стиле» с нуля, выбросив код выбранного превью, нельзя: человек получит не то, что выбрал. На панели в это время — строка «Доводим вариант Б» (её поставил `ad.py stage build --note` на выборе).

Порядок этапа: копия «до» → маршрут знаний → дизайн-система → медиа → доводка страниц → круги правок с человеком. После каждого шага, который меняет проект, — **блок `aidesign` в памяти проекта обновляется сразу** (`phases/6-handoff.md` §2), а не в конце: прерванный прогон оставляет правила верными на момент остановки.

## 0. Копия «до» — перед первой правкой, без исключений

Перед первой правкой существующих файлов — полная копия проекта. **Без исключений**: на входе «готовый сайт» — всегда; на новом сайте копия крошечная и делается за секунду — тоже делается.

```bash
python3 .aidesign-work/backup.py create --root . --reason "до"
```

- На готовом сайте копия «до» уже сделана при выборе направления, перед первым `DESIGN.md` (`phases/3-previews.md` §8) — она есть в `state.js` → `backups`; второй раз не делается.
- Копия ложится в `.aidesign-work/backups/<дата-время>-до/` — файлы и `manifest.json` с суммами; после записи скрипт читает каждый файл обратно и сверяет. Не скопировано только то, что программа создаёт заново (`node_modules/`, `.git/`, `.aidesign-work/`, кэши сборок).
- Сразу — `python3 .aidesign-work/ad.py backup add --id <id из вывода> --reason "до" --bytes <размер из вывода>`: копия видна на панели и попадёт в отчёт.
- **Больше 500 МБ** — скрипт ничего не пишет и выходит с кодом 1, назвав размер. `ad.py ask action --note "копия проекта N МБ"` и вопрос: «Копия проекта займёт N МБ на диске. Делаю (а) или ты сначала сам сохранишь папку куда-нибудь и скажешь «готово» (б)?». «а» — тот же вызов с `--force`.
- **Сверка не сошлась** (код 1, копия помечена `BROKEN`) — ни одной правки: одна строка человеку, что копия не удалась и почему, повтор после «да».
- **Проект под git** — вдобавок к копии: `ad.py ask action --note "ветка для редизайна"` и вопрос: «Сделаю отдельную ветку `aidesign/redesign`, чтобы старый вид остался в один клик (а), или коммит «до редизайна» в текущей (б)?». Копия «до» от ответа не зависит.
- Копии не удаляются без слова человека. Откат — только по его «верни как было»: `backup.py restore --root . --id <id>` без `--yes` показывает план, с `--yes` — после «да» (`ad.py ask action`); перед откатом скрипт сам копирует текущее состояние, лишние файлы уносит в `backups/<id>-лишнее/`.

## 2. Дизайн-система — первой

Стиль проекта живёт в одном месте — `design-system/`. Сайт берёт его только оттуда: ни одного значения цвета или шрифта мимо токенов. Пока дизайн-системы нет, не собирается ни одна страница.

**Новый сайт:**

1. `design-system/tokens.css` — источник: `:root { … }` с переменными по префиксам `--color-`, `--font-`, `--space-`, `--radius-`, `--shadow-`, `--motion-` — значения из `DESIGN.md`, то есть из выбранного превью; тёмная тема, если она есть в направлении, — `[data-theme=dark]` или `@media (prefers-color-scheme: dark)`.
2. `design-system/styleguide.html` — витрина в выбранном стиле: цвета с ролями, шрифты и шкала, отступы, кнопки, карточки, поля формы, образцы разделов. Подключает `tokens.css`, проходит `check.py`. Её видит человек — и следующий агент берёт компоненты отсюда.
3. `design-system/README.md` — как подключить: одна строка `<link rel="stylesheet" href="design-system/tokens.css">`, правило «значения только через `var(--…)`», где витрина, как проверить; для человека и для агента.
4. `design-system/CHANGELOG.md` — первая запись: дата — «создана по направлению «<name>»» — почему (одна строка из `direction.md`).
5. `python3 .aidesign-work/designsystem.py export --root .` — выводит `design-system/tokens.json` из `tokens.css`. Руками JSON не правится.
6. `DESIGN.md` ссылается на `design-system/` строкой в разделе токенов.

Значения цвета и шрифтов из выбранного превью переходят в токены как есть, а сам код превью при доводке переводится на `var(--…)` — вид не меняется.

**Готовый сайт:** сначала текущий стиль вытаскивается в `design-system/` **«как было»** — настоящие значения из CSS сайта (`knowledge/язык/извлечь-стиль-с-сайта.md`, путь 3), без «улучшений»; в `CHANGELOG.md` — запись «как было: вынесено из сайта без изменений». Затем сайт переводится на эти токены (вид не меняется — проверь снимками), и только потом правки дизайна — через токены, каждая строкой в `CHANGELOG.md`. Без согласия ничего не переименовывается: ни файлы, ни классы, ни адреса.

После — блок `aidesign` (дизайн-система создана — событие).

## 3. Медиа — план, генерация, подготовка

Источник — из `vkus.md` → «Медиа» (свои · генерация · вперемешку · кодом · плашки). Читать: `knowledge/медиа/INDEX.md`, затем `knowledge/медиа/генераторы.md` и файлы промптов по виду медиа.

**План медиа** — `media-plan.md` в папке прогона, до первой генерации. Строка на каждое место страницы:

| Место | Источник | Сервис и модель | Промпт или файл | Размер и формат | Что прочитано |
|---|---|---|---|---|---|
| фон первого экрана | генерация | Higgsfield · Nano Banana | «утро у окна…» (промпт целиком) | 16:9, WebP 640/1280/1920 | инструкция сервера + aimaster `guides/current/…` |
| фото зала | свой | — | `референсы/свои/зал-2.jpg` | 4:5 | — |
| пар над чашкой | кодом | — | рецепт 1 (частицы) | — | `knowledge/медиа/кодом-вместо-генерации.md` |

- **Материал из превью** — уже есть в папке круга выбранного варианта: он переходит в план строкой «из превью» и в проект через подготовку и опись (шаги 7–8 цикла ниже), без новой генерации.
- **Инструкции до промпта, по порядку**: инструкции самого сервера генератора (их отдаёт MCP) → установленный скилл под эту модель (`python3 .aidesign-work/media.py skills`; aimaster — по `knowledge/медиа/aimaster.md`) → `knowledge/медиа/` AI Design. Что прочитано — в столбец плана.
- **Бюджет** — если в интервью его не назвали, а в плане есть генерация: один вопрос перед первой платной генерацией с `ad.py ask action --note "бюджет на генерацию"` — «На картинки и видео тратим до N кредитов Higgsfield?» — и `ad.py media budget --limit N --unit кредитов`. «Только бесплатное» — места генерации уходят в свои, кодом или плашки.

**Цикл одной генерации** — генерирует **только ведущий агент**, не субагенты: один счётчик бюджета и одна опись. По порядку:

1. Баланс и цена — инструментами сервиса, где они есть. Цену сервис не называет — скажи это; потолок принимается — поставь его не выше остатка бюджета и считай по факту. Цена неизвестна и потолок не принимается — **вслепую не генерируй никогда**: проверь по остатку бюджета оценкой сверху (`ad.py media check --amount` по самой дорогой известной цене этой модели у этого сервиса, не по памяти) или, если такой оценки нет либо она не влезает, сначала спроси человека с суммой (`ad.py ask action`). Подробно — `knowledge/медиа/генераторы.md` §3.
2. `python3 .aidesign-work/ad.py media check --amount <цена>` — код 0: в бюджете, дальше без вопроса; код 1: выйдет за сумму или бюджета нет — новый вопрос человеку с суммой (`ad.py ask action`).
3. Задача — промпт по прочитанным инструкциям; ожидание — инструментом ожидания сервиса, повторных задач не ставить, пока первая не ответила.
4. `python3 .aidesign-work/ad.py media spend --service <id> --amount <сколько списано> --unit <как в бюджете> --item "<место>"` — сразу после ответа сервиса.
5. `python3 .aidesign-work/media.py fetch --url <ссылка> --out assets/raw/<имя>` — ссылки сервисов временные; тип проверяется по первым байтам.
6. Посмотреть **глазами** — картинку в полный размер по `knowledge/медиа/качество-фото.md`, видео целиком и покадрово (руки, предметы, свет, шов петли). Не годится — одна правка промпта; **не больше двух перегенераций одного места без вопроса человеку**, третья — только после его «да».
7. `python3 .aidesign-work/media.py prep image --in assets/raw/<имя> --out assets/img` (WebP и AVIF 640/1280/1920) или `media.py prep video --in … --out assets/video` (MP4 H.264 без звука, WebM, постер); видео по прокрутке — по рецепту `knowledge/медиа/промпты-видео.md`.
8. `python3 .aidesign-work/media.py record --slot "<место>" --file <файл> --source <id сервиса|own|code|placeholder> --prompt "<промпт>" --model "<модель>" --alt "<что на картинке>"` — опись `assets/media.json`; по ней следующий агент перегенерирует место тем же промптом.

Свои файлы человека проходят шаги 6–8 (`--source own`), код и плашки — только шаг 8. Человеку — строка после каждой готовой группы: «Фон первого экрана и три фото готовы — потрачено 48 из 300 кредитов». Сбои генерации — таблица «Сбои» в `knowledge/медиа/генераторы.md`.

### 3а. Сайт как фильм — только по выбору человека

Когда выбранный вариант построен на «фильме» (прокрутка ведёт камеру через сцены) или человек сам попросил «как кино, сцена за сценой». Сам скилл его не навязывает: это дорогой путь — 5–7 сцен генерации и столько же роликов. Правила, шаблоны промптов и шаги целиком — `knowledge/медиа/сайт-как-фильм.md`; команды:

1. `python3 .aidesign-work/film.py plan --beats 6 --camera fly --services <id подключённых> --title "<название>"` — план сцен `film-plan.json` и `film-plan.md`; камера — `fly` (полёт со связками), `walk` (проход), `locked` (один ракурс). Тексты битов — только слова человека, иначе заглушки.
2. `python3 .aidesign-work/film.py models --services <id>` — какие модели принимают начальный и конечный кадр; код 1 — подходящей нет: человеку прямо, стыки заменяются перетеканием.
3. Телефон — вопрос всегда (вдвое больше роликов): `ad.py ask action --note "фильм: телефонная версия"`.
4. `python3 .aidesign-work/film.py estimate --plan film-plan.json --image-cost <цена кадра> --video-cost <цена ролика> --unit <единица бюджета>` → `ad.py media check --amount <итог>`; код 1 — вопрос с суммой. Сначала **один пробный кадр** и взгляд на него, потом вся генерация — циклом §3.
5. Кадры стыков — из готовых роликов: `film.py frames <ролик> --last <кадр.png>`; кодирование — `film.py encode <ролик> --desktop <файл.mp4>` и `--mobile`.
6. `python3 .aidesign-work/film.py page --plan film-plan.json --out <папка сайта>` — страница на движке `scroll-film.js`; чужой `index.html` не перезаписывается.
7. `python3 .aidesign-work/film.py seams --page http://127.0.0.1:8000/ --out .aidesign-work/<dir>/seams` — снимки до и после каждого стыка (браузерный модуль); посмотри глазами, затем `--reduced-motion` — должна остаться обычная страница.

Без генераторов или бюджета фильм не собирается: одна строка человеку и обычная страница с видео по прокрутке (`knowledge/движение-и-медиа/видео-в-сайт.md`).

## 4. Кто собирает

Доводка — субагенту по заданию `<skillDir>/prompts/build.md` (путём, не пересказом). Он получает: корень проекта, **файл выбранного превью и папку его круга** (это основа страницы), `DESIGN.md`, `design-system/`, `direction.md` с маршрутом и «Правками к выбранному», `vkus.md`, `brief.md`, `media-plan.md` и `assets/media.json`, адрес локального сервера, `audit.md` на готовом сайте и абсолютный путь к `<skillDir>/knowledge/`. **Не получает** твоих рассуждений о вариантах: только решения.

- Большая работа (сайт из многих страниц, редизайн нескольких страниц) — несколько сборщиков **по разным файлам**, чтобы двое не писали в одно место; дизайн-система — первой, одним сборщиком, первый экран из выбранного превью — первым, остальные после.
- Генерацию сборщик не запускает: нужное медиа он называет в отчёте, ты добавляешь место в план и проходишь цикл §3.
- Субагентов в среде нет — доводи сам по тому же `prompts/build.md`.
- **Проверка на каждую правку — по желанию, только в Claude Code.** Перед первой правкой можно предложить одной строкой (можно в том же сообщении, что вопрос о ветке git): «Включить проверку шаблонности после каждой правки? Она только подсказывает, ничего не блокирует (а) или не нужно (б)». Перед вопросом — `ad.py ask action`. После «а» — блок хука из `knowledge/язык/антипаттерны.md#exceptions` в `.claude/settings.local.json` проекта, команда — `python3 "$CLAUDE_PROJECT_DIR/.aidesign-work/check.py" --hook`; файл настроек уже есть — дописать, не перезаписывая. Нет «да» — хука нет, полная проверка остаётся на Проверке.
- Человеку — одна строка после каждой заметной части: «Первый экран и раздел услуг готовы — 2 из 5». Каждая часть — событие для блока `aidesign`.

## 5. Новый сайт — доводка

- **Основа — выбранное превью.** Его HTML становится `index.html` (или первой страницей фреймворка проекта): тот же код, та же разметка первого экрана, тот же главный приём; значения стиля переводятся на токены, материал из папки круга заменяется подготовленными файлами из `assets/`. Не пересобирай первый экран заново.
- **Все разделы.** По «Разделам» из `vkus.md` и брифа достраиваются все разделы страницы (или все страницы сайта) в той же ведущей стилистике, с одним громким приёмом на экран; главный приём превью не теряется и не дублируется на каждом экране.
- **Стек — самый простой, который выдержит задачу**: одна страница — чистые HTML, CSS и ванильный JS без сборки; проект уже на фреймворке — его фреймворк. Новую зависимость — только если без неё приём не сделать (например, GSAP для сцен прокрутки — с CDN), и одной строкой человеку.
- **Стиль — только из `design-system/tokens.css`**: страницы подключают его первым, своих значений цвета, шрифта, отступа не держат. Нужен новый токен — сначала в `tokens.css`, строка в `CHANGELOG.md`, `designsystem.py export`, потом в коде.
- **Раскладка файлов** — по схеме `knowledge/структура-проекта.md`: страницы в `pages/`, картинки в `assets/img/`, видео в `assets/video/`.
- **Тексты — его, и дописываются вместе с ним**: заголовки, цены, контакты, отзывы — только из брифа и ответов. Каждому новому разделу нужен текст — собери, чего не хватает, **одним вопросом** на раздел или на страницу (`ad.py ask action --note "тексты раздела «Услуги»"`): «Для раздела «Услуги» нужны названия и цены — пришли или напиши «заглушки»». Нет ответа или «заглушки» — видимая заглушка `[ЦЕНА — впиши]` и `ad.py add report "заглушка: цены в разделе услуг"`. Правдоподобную выдумку не пишешь никогда.
- **Медиа** — по плану §3: свои, сгенерированные, код или подписанные плашки и список кадров для съёмки (`knowledge/движение-и-медиа/фото.md`). Чужие фото не ставятся.
- **Открыто как файл.** Видео — прямо `<video src>`; всё, что по `file://` не загрузится, — с плашкой «Открыто как файл… Откройте: http://localhost:ПОРТ/…» (`knowledge/движение-и-медиа/видео-в-сайт.md`). Человеку адрес даётся только http — с сервера, который отдаёт файлы кусками (Range, §8).

## 6. Готовый сайт

`knowledge/движение-и-медиа/готовый-сайт.md` — главное правило этапа: то, что работает, продолжает работать. Копия «до» уже сделана (§0) — без неё сюда не заходят. Выбранное превью здесь — образец первого экрана после редизайна: его решения переносятся в код сайта слоями, а не заменой страницы.

1. **Недостающее по схеме** — `python3 .aidesign-work/scaffold.py apply --root . --kind page|site --title "…"`: создаёт только отсутствующее (`design-system/`, `DESIGN.md`, файл памяти, строки `.gitignore`) и ничего не перезаписывает; раскладку работающего сайта он не трогает.
2. **Перенос файлов — только с согласия.** `scaffold.py plan` показал раскладку как `propose` — это предложение, не план работ. Хочешь предложить — `ad.py ask action --note "разложить файлы сайта"` и вопрос со списком «что куда» и какие адреса страниц изменятся. После «да»: новая копия (`backup.py create --reason "до-переноса"` и `ad.py backup add`), перенос, правка всех ссылок (`href`, `src`, `url(…)`, импорты), проверка, что каждая страница и каждый ресурс открываются (`knowledge/структура-проекта.md`, «Готовый сайт»). Нет «да» — файлы лежат где лежали.
3. **Слои от безопасного к рискованному:** токены и шрифты → отступы и ритм → компоненты → раскладка разделов → движение и медиа. После каждого слоя — собственные проверки проекта (тесты, сборка), `python3 .aidesign-work/check.py <файлы сайта>` и строка в блоке `aidesign`.
4. **Опись «не сломать» из `audit.md`** — ни одного переименованного `id`, класса, `data-*`, поля формы, адреса ссылки. Нужен новый класс — рядом со старым.
5. **Не удалять** скрипты аналитики, пиксели, виджеты, «лишние» файлы. Ненужное — только с согласия и переносом в `.черновики/`.

## 7. Платное — кроме генерации

Генерация медиа — по бюджету (§3). Остальное платное — платный шрифт, платный сервис, библиотека с платной лицензией — нигде по умолчанию:

1. сначала бесплатная замена — свободный шрифт, код, его собственный материал;
2. замены нет и без этого направление разваливается — `ad.py ask action --note "платное: что и сколько стоит"` и вопрос с **суммой**: «Шрифт <название> стоит около <сумма> за сайт. Покупаешь (а) или беру свободный похожий (б)?»;
3. только после «а»; покупает человек сам. Сумму не знаешь точно — назови вилку и откуда она.

## 8. Круги правок по живой странице — до «готово»

Доводка не заканчивается на «сборщик сдал». Человек смотрит **живую страницу** и правит, пока не скажет «готово».

1. Сборщик вернул отчёт — проверь сам выборочно: открой страницу по http сервером с Range (`python3 .aidesign-work/ad.py --serve-http 8000 --directory <папка сайта>` в фоне — он отдаёт файлы кусками, без этого видео по прокрутке стоит на первом кадре; или команда проекта, если её сервер тоже отдаёт куски), сам приём работает (видео идёт за прокруткой, канвас рисует), заглушки и допущения — `ad.py add report "…"` / `ad.py add assumptions "…"`. Новые токены, которые просил сборщик, — в `tokens.css`, `CHANGELOG.md` и снова `designsystem.py export`.
2. Покажи человеку: открой страницу во вкладке встроенного браузера сам (как превью на Превью), дай адрес `http://localhost:ПОРТ/` и, если есть, снимки 1280 и 390. Перед вопросом — `ad.py ask action --note "круг правок N: что поменять"`:

```
Страница готова целиком: http://localhost:8000/
Открыл у себя и проверил: видео идёт за прокруткой, все разделы на месте, на телефоне ничего не вылезает.
Заглушки остались в двух местах: цены в «Услугах» и адрес в подвале — пришли, вставлю.

Что поменять? Пиши как удобно: «в услугах шрифт мельче», «фото зала другое», «кнопку зелёной».
Всё нравится — напиши «готово», и я перейду к проверке.
```

3. Ответ — дословно в `brief.md` → `## Дополнения`; правки — сборщику с его словами (или сам, если это строка-две); меняется стиль — сначала токен и `CHANGELOG.md`; новое медиа — через план и цикл §3, в бюджете. Затем снова шаг 1–2 — следующий круг правок.
4. Кругов — сколько нужно. Правка, которая меняет направление целиком («давай всё-таки тёмный»), — одна строка-вопрос: «Это уже другое направление — показать три превью заново (а) или поменять в этом (б)?».
5. **«Готово»** (или «да, всё», «отлично, дальше») — строка человеку, что теперь есть, блок `aidesign` по факту, `ad.py stage check` и `phases/5-check.md`. В режиме `auto` круг правок один: покажи страницу и иди на Проверку, если человек молчит.
