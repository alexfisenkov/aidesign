# Превью — три настоящих варианта и круги до «нравится»

`ad.py stage previews`. Человек видит на панели три живые мини-страницы первого экрана на своём тексте и выбирает. Не нравится — уточняющие вопросы и новый круг; и так, пока не скажет «оно». **Сборка не начинается без явного выбора.**

**Превью — настоящие.** Человек выбирает глазами и должен смотреть на то, что реально будет на сайте: каждое превью — рабочий первый экран с **настоящим главным приёмом** своего варианта (видео по прокрутке, видеофон, шейдер, частицы, 3D, морфинг, эффекты мыши, параллакс, сцена прокрутки) на **настоящем материале** — его текстах, его фото и видео или медиа, сгенерированном в его бюджете. Никаких «намёков», «здесь будет анимация», стоп-кадра вместо движения. Вес превью решается одним общим лёгким файлом на три варианта и ленивой загрузкой, а не подменой приёма. Единственное исключение — материала нет и получить его нельзя (раздел 3); тогда человеку прямо сказано, чего в превью нет и почему.

Читать перед первым кругом: `knowledge/движение-и-медиа/превью.md` (целиком — это правила этого этапа), `knowledge/язык/антипаттерны.md`, `knowledge/язык/сочетание.md`, `knowledge/движение-и-медиа/поверхности.md` (раздел своей поверхности), файлы стилей из `knowledge/язык/стили/INDEX.md`, которые назвал профиль; на готовом сайте — ещё `knowledge/движение-и-медиа/готовый-сайт.md`, раздел 2. Главному приёму нужен материал — ещё `knowledge/медиа/INDEX.md` (по месту на странице) и, для видео, `knowledge/медиа/промпты-видео.md`, раздел «Видео для превью».

## 1. Перед первым кругом

Скажи путь одной строкой — из последнего раздела `vkus.md`: «Путь: лендинг · природный · фото-ведущие · спокойное движение». Не вопрос, а чтобы человек видел, куда идём.

## 2. Три направления — план круга

Придумываешь ты, строят субагенты. Режим — по `превью.md`: **«отход»** на новом сайте, **«внутри идентичности»** на готовом сайте (кроме ответа «переделать полностью») и при доработке одного варианта.

Для каждого варианта — карточка в `rounds/NN/plan.md`:

| Поле | Пример |
|---|---|
| Буква и название для человека | А — «Тихая редакция» |
| Семейство (`knowledge/язык/стили/`) | редакционный |
| Предмет из мира | меню бистро на грифельной доске |
| Одна фраза | крупная антиква, фото справа во весь рост, много воздуха |
| Главная ось | типографика (у Б — раскладка, у В — цвет и материал) |
| Шрифты, цвета (hex), раскладка, движение | конкретно, без «современный и чистый» |
| Главный приём и его материал | видео по прокрутке — общий `rounds/NN/scene-720.mp4`; шейдер-фон — код; фото справа — `rounds/NN/hero.webp` (своё) |
| Что от профиля вкуса | «засечки», «утро у окна», «без капса» |
| Цена | вес, сложность, что нужно от человека — фото, видео, 3D-модель |

Перед стартом — две проверки из `превью.md`: **семейства** (три подписи не совпадают и не взаимозаменяемы) и **фразы** (три фразы рядом не «рифмуются»). Различаются **главные оси** — композиция, шрифт, ритм, — а не только цвет. Один вариант может быть смелее, чем просил профиль: человек часто узнаёт своё, когда видит чуть больше, чем умел сказать.

## 3. Материал главного приёма — до превью

Сначала материал, потом превью: превью без материала покажет не то, что будет. По каждой карточке реши, что нужно главному приёму, и добудь это **до** того, как отдать превью субагентам. Источник — из `vkus.md` → «Медиа».

| Приёму нужно | Откуда, по порядку |
|---|---|
| ничего, кроме кода — шейдер, частицы, градиент, шум, морфинг SVG, эффекты мыши, параллакс, 3D из простых форм | код, бесплатно, всегда настоящий (`knowledge/медиа/кодом-вместо-генерации.md`) |
| фото — первый экран, фото справа | свои картинки человека; иначе — генерация в бюджете, если генерация в превью разрешена (ниже), **по одной главной картинке на превью**; иначе — плашка в пропорции с подписью |
| видео — видеофон, видео по прокрутке, видео за курсором | свой ролик; иначе — генерация в бюджете; **один общий лёгкий файл на все три превью** |
| 3D-модель, звук | свой файл; иначе — генерация в бюджете; иначе — сцена из простых форм кодом |

- **Свои картинки и видео человека** — копии в папку круга `rounds/NN/` (не ссылки на его папки: панель отдаёт по http только папку прогона). Фото — `python3 .aidesign-work/media.py prep image --in <файл> --out .aidesign-work/<dir>/rounds/NN/` и в превью — версия шириной 1280; видео — по рецепту «Видео по прокрутке: один лёгкий файл» из `knowledge/медиа/промпты-видео.md`: 720p, частые ключевые кадры, без звука, постер-кадр рядом. Так три превью одновременно не грузят компьютер, а приём настоящий.
- **Генерация в превью — только в трёх случаях**, и всегда в пределах бюджета:
  1. генерация в превью разрешена в интервью — так записано в `vkus.md` → «Медиа»;
  2. человек сам просит «покажи с настоящими картинками»;
  3. главного приёма без неё не показать: нужен материал главного приёма — видео по прокрутке, видеофон, модель или главное фото, на котором держится приём (фото первого экрана, если вариант построен вокруг него), — а своего нет (история 73; это и есть «сначала материал, потом превью»). Остальные фото варианта под этот случай не попадают.

  В остальных случаях — свои картинки человека или плашки, генерация ждёт Сборки. Бюджета нет — сначала вопрос о бюджете (банк, В61) с `ad.py ask action`; «только бесплатное» — генерации нет. Генерирует **только ведущий агент**, по циклу `knowledge/медиа/генераторы.md` §6: инструкции модели (сервера, установленного скилла, затем `knowledge/медиа/`) → `ad.py media check --amount <цена>` → задача → ожидание → `ad.py media spend --service <id> --amount <сколько> --unit <как в бюджете> --item "превью: <место>"` → `media.py fetch --url <ссылка> --out .aidesign-work/<dir>/rounds/NN/<имя>` → посмотреть глазами → `media.py prep`. В превью — по одной главной картинке на вариант; видео — один общий ролик на три. Промпт и модель — строкой в карточку `plan.md`: на Сборке их не придумывают заново.
- **Человек сам просит** «покажи с настоящими картинками» — тот же цикл, по одной главной картинке на превью в пределах бюджета. Цена неизвестна — правило «вслепую не генерируем» из `knowledge/медиа/генераторы.md` §3.
- **Материала нет и получить его нельзя** — своего нет, генератора нет или бюджета нет («только бесплатное»): ближайший честный вариант — плашка в пропорции с подписью, код вместо фото там, где это уместно, для видео — постер-плашка со строкой «здесь будет видео по прокрутке». Это исключение пишется в карточку и **прямо говорится человеку** в сообщении круга: «Видео в превью нет: своего ролика нет, а генерацию мы не включали. В сборке здесь будет прокрутка по видео — для этого нужен ролик 10–15 секунд». Молча подменять приём нельзя.

## 4. Круг: собрать, проверить, показать

1. **Открыть круг:** `ad.py round new` — печатает папку `rounds/NN/`.
2. **Собрать три превью** — три субагента **одним сообщением**, каждому задание `<skillDir>/prompts/preview.md` путём и свои входные данные: путь к своей карточке в `plan.md`, путь к файлу `rounds/NN/a.html` (b, c), пути к `brief.md`, `vkus.md`, `refs.md`, пути к материалу главного приёма в `rounds/NN/`, адрес этого превью на сервере панели (`http://localhost:PORT/<dir>/rounds/NN/a.html`) и, при доработке, путь к выбранному превью прошлого круга. Субагентов нет — собери по тому же заданию сам, по очереди.
3. **Проверить:** `python3 .aidesign-work/check.py .aidesign-work/<dir>/rounds/NN/` — ноль находок; есть — верни файл его субагенту с находками или поправь сам, проверь снова.
4. **Критик** — один субагент по `<skillDir>/prompts/critic.md`, режим «превью»: три файла круга, `vkus.md`, раздел «Медиа» из него и список файлов материала в папке круга, адреса превью на сервере — без твоего плана и рассуждений. Он проверяет, что варианты по-настоящему разные, нет примет шаблона и «каши» стилей, а приёмы — настоящие. Блокирующее — исправить до показа.
5. **Снимки 1280 и 390:** `python3 .aidesign-work/shots.py .aidesign-work/<dir>/rounds/NN/a.html .aidesign-work/<dir>/rounds/NN/b.html .aidesign-work/<dir>/rounds/NN/c.html` — кладёт `a-1280.png`, `a-390.png` и так далее рядом с превью. Панель показывает снимок в карточке и под живой страницей в крупном просмотре: его видно в любом браузере, даже там, где живое превью в рамку панели не пускают. Код 1 — нет Playwright или браузера: строку `!` прочитай, прогон идёт дальше без снимков.
6. **Записать варианты на панель** — после того, как все три готовы и проверены:
   `ad.py round option --id a --title "Тихая редакция" --src rounds/NN/a.html --note "редакционный · антиква и воздух · ось: шрифт · лёгкая"` — и так же `b`, `c`. В заметке: семейство · одна фраза · главная ось · цена; исключение из раздела 3 — тоже в заметку («без видео: ролика нет»). Снимки рядом с превью `round option` подхватит сам (иначе — `--shot1280`, `--shot390`).
7. **Открыть каждое превью самому и проверить, что приём работает** — до вопроса, всегда. Файлы на диске и даже снимки — ещё не «человек видит то, что должен».
   - **Только по http**, адресом сервера панели: `http://localhost:PORT/<dir>/rounds/NN/a.html` (b, c). Никогда по `file://`: так браузер не даёт превью читать соседние файлы через `fetch`, и видео или модель молча не загрузятся — человек увидит постер вместо приёма.
   - **Claude desktop и Claude Code с браузером** — открой каждое превью во **вкладке встроенного браузера** сам (`preview_start` с адресом сервера, затем `navigate` на каждое превью), а не проси человека кликать по ссылкам. Нет встроенного браузера — Playwright или браузер агента по тем же адресам.
   - **В каждой вкладке проверь сам приём**, а не только то, что страница нарисована: видео — `readyState` не меньше 2, при прокрутке `currentTime` меняется, видеофон играет; канвас и шейдер — рисуют (пиксели не пустые, кадры идут); 3D — сцена видна и отзывается; эффект мыши — отзывается на движение указателя; морфинг и параллакс — двигаются; текст человека на месте, нет плашки «Открыто как файл», нет ошибок в консоли. И на 390 — экран законченный.
   - Приём не работает — исправь до показа (верни субагенту с тем, что увидел, или поправь сам) и проверь снова. Посмотри и снимки (`Read` картинки): не пустые, текст человека на месте.
   - Ни браузера, ни Playwright — скажи человеку прямо: «Открыть превью сам не смог — проверь, пожалуйста, что в каждом работает видео», и дай три адреса.
8. **Только теперь — ожидание и вопрос.** `round option` закрывает ожидание, поэтому `ask` идёт **после** третьего `round option` и проверки, прямо перед сообщением: `ad.py ask previews --note "круг N: какой вариант ближе"`.

Сообщение человеку:

```
Круг 1 — три превью на панели: http://localhost:PORT/dashboard.html
Открыл все три во вкладках браузера и проверил: видео по прокрутке работает в каждом.
Смотри по адресам: http://localhost:PORT/<dir>/rounds/01/a.html · …/b.html · …/c.html
Открылось как файл (адрес начинается с file://) — видео и эффекты не загрузятся, открой по адресам выше.
Нажми на превью на панели — откроется крупно, сверху переключатель «компьютер / телефон».

А — «Тихая редакция»: крупные буквы с засечками, видео по прокрутке во всю ширину, много воздуха.
Б — «Мастерская»: тёплая бумага, заголовок поверх того же видео в рамке, рукописные пометки.
В — «Вечерний свет»: тёмный фон, видео приглушено, медленное появление текста. Цена: тяжелее страница.

Я бы взял Б: ближе всего к «кофейне» и «льну» из твоих ответов.

Ответь как удобно:
• «Б» — если это оно: доведу Б до готового сайта — все разделы, тексты с тобой, медиа;
• «Б, но …» — возьму Б и первым делом внесу твои правки;
• «доработай Б» — покажу три доработки Б;
• «не то» — спрошу, что понравилось, и покажу новый круг.
```

Без шкал и оценок, без «вариант 1 из 3», без кода. Цена «навороченного» — до выбора. Строка о проверке — только о том, что ты действительно проверил; исключение из раздела 3 — отдельной строкой: «Видео в превью нет: …, вот почему». Ссылки человеку — только `http://`, никогда путь к файлу.

Снимки есть, а клиент умеет прикладывать файлы к ответу, — приложи три снимка `-1280.png` к сообщению: так человек видит варианты прямо в чате, даже если панель у него не показывает превью. В Claude desktop добавь строку: «Не видно на панели — нажми под вариантом „Открыть в новой вкладке“».

## 5. Ответ человека

Любой ответ сначала — дословно в `rounds/NN/feedback.md` и `ad.py round feedback --text "<его слова>"`. Затем:

| Человек сказал | Что делать |
|---|---|
| «Б», «оно», «да, Б», «нравится Б» | `ad.py round choose --id b` → раздел 8 |
| «Б, но шрифт крупнее и потеплее» — конкретные правки | это выбор с правками: `ad.py round choose --id b`, правки — в `direction.md` → «Правки к выбранному» и первым шагом доводки → раздел 8 |
| «доработай Б», «Б, но покажи ещё», «Б, но не уверен» | `ad.py round refine --id b` — новый круг доработки: три варианта Б по трём разным осям из его «но»; режим «внутри идентичности» → снова раздел 4 |
| «в А шрифт, в В цвет» — назвал части | это уже ответ на уточняющие вопросы: `ad.py round choose --id none`, новый круг с этими частями (`ad.py round new`) |
| «не то», «ничего не нравится», «не моё» | `ad.py round choose --id none` → уточняющие вопросы, раздел 6 |
| «ну наверное Б», «не знаю, вроде Б» | не выбор. Один вопрос: «Довожу Б до готового сайта (а) или ещё круг (б)?» — с `ad.py ask previews`; «а» → выбор, «б» → раздел 6 |
| «выбери сам» | бери рекомендованный, `ad.py round choose --id <буква>` и `ad.py add assumptions "направление выбрано по рекомендации — круг N"`; одна строка: «Беру Б — передумаешь, скажи» |
| прислал картинку «вот так хочу» | новый референс (`ad.py ref add …`, `refs.md`) → уточняющие вопросы, раздел 6 |
| «в Б нет видео», «пусто», «не вижу» | не отзыв о вкусе, а сбой показа: открой этот вариант сам по http и проверь приём (раздел 4, шаг 7), почини, дай адрес снова |

## 6. «Не то» — уточняющие вопросы

Перед вопросами — `ad.py ask previews --note "круг N: что понравилось и что нет"`. Это **одно сообщение даже в форме «по одному»**: человек сравнивает три варианта сразу, по одному вопросу он забудет, что видел.

```
Понял, не то — помоги попасть точнее, коротко:
1. Что понравилось в А? а) шрифт б) цвет в) как расположено г) ничего
2. Что понравилось в Б? а) шрифт б) цвет в) как расположено г) ничего
3. Что понравилось в В? а) шрифт б) цвет в) как расположено г) ничего
4. Чего не хватает во всех трёх? а) теплее б) смелее в) спокойнее г) другое — напиши
Можно своими словами: «в А шрифт, в В цвет, всё слишком тёмное».
```

Можно добавить один вопрос по сути — где профиль явно разошёлся с реакцией («Ты выбирал светлое, а сейчас тянет к В — может, тёмный всё-таки ближе?»). Ответы — в `feedback.md`; то, что меняет профиль, — в `vkus.md` и, если это отменяет сказанное раньше, — в `brief.md` → `## Дополнения`.

**Новый круг** строится на ответах: понравившееся остаётся, нелюбимое уходит, «не хватает» становится главной осью. Хотя бы один вариант — направление, которого ещё не было: иначе круги ходят по кругу. Материал прошлого круга, если подходит, переиспользуй — копией в новую папку круга, без новой генерации. Затем — раздел 4 с новым номером.

## 7. После трёх кругов без выбора

Перед четвёртым кругом — не ещё три новых, а выбор пути. `ad.py ask previews --note "три круга без выбора — как дальше"`:

```
Три круга — и пока не оно. Давай по-другому:
а) смешать понравившиеся части: шрифт из 1А, цвет из 2В, расположение из 3Б — покажу три смеси;
б) взять самый близкий вариант и показать его смелее и спокойнее;
в) ещё один круг совсем других направлений;
г) расскажи своими словами, что раздражает больше всего, — я перестрою с нуля.
Я бы взял а: ты уже назвал всё, что нравится, осталось сложить.
```

- **«а» — смесь:** `ad.py round new`, три варианта = три разных смеси названных частей.
- **«б» — смелее / спокойнее:** `ad.py round refine --id <ближайший>`: `a` — он же, доведённый; `b` — смелее (крупнее шрифт, сильнее контраст, один громкий приём); `c` — спокойнее (меньше цвета и движения, больше воздуха).
- **«в»** — новый круг в режиме «отход» от всего показанного. **«г»** — его слова в `vkus.md`, новый круг.

Кругов сколько нужно. Каждые следующие три без выбора — снова этот вопрос.

## 8. Выбор сделан — направление и доводка

Выбранный вариант не пересобирается «по направлению» с нуля, а **доводится до дела**: файл превью — основа страницы, его код, приём и материал переходят в сайт как есть, и дальше до него достраивается всё остальное. Человек выбрал то, что видел, — то и получает, только целиком.

1. **`direction.md`** в папке прогона: что выбрано (круг, буква, путь к файлу превью), его слова о выборе, «Правки к выбранному» (его «но», если было), что нравилось в соседних вариантах и что отвергнуто, почему.
2. **Первый `DESIGN.md`** в корне проекта по формату `knowledge/язык/design-md.md`: токены — **настоящие значения из выбранного превью** (цвета, шрифты, шкала, радиусы), во фронтматтере `aidesign: "<версия скилла>"` и `direction: "<семейство · название>"`, разделы с 1 по 10, пустые опущены. Его читает сборка. На Передаче он доводится по собранному сайту.
   - **`DESIGN.md` — заглушка от `scaffold.py`** («Направление ещё не выбрано») — она наша: заменяется без вопроса.
   - **`DESIGN.md` уже есть и он не от AI Design** — не перезаписывай молча. `ad.py ask action --note "DESIGN.md уже есть — обновить, заменить или объединить"`, вопрос «а) дополнить его нашими решениями, б) заменить (старый уйдёт в `.aidesign-work/<dir>/DESIGN.old.md`), в) объединить — покажу, что меняется»; без ответа — «а».
3. **`ad.py direction set --name "Мастерская" --summary "тёплая бумага, заголовок поверх фото рук, тихое движение" --file DESIGN.md`**.
4. **Блок `aidesign` в памяти проекта** — обновить сразу (направление выбрано — событие, `phases/6-handoff.md` §2): название направления, ссылка на `DESIGN.md`.
5. Одна строка человеку о том, что будет дальше: «Беру Б — «Мастерская». Довожу его до готового сайта: тот же код и то же видео, все разделы, тексты допишем вместе, медиа — по плану. Покажу живую страницу, правим, пока не скажешь «готово»».
6. `ad.py stage build --note "Доводим вариант Б — «Мастерская»"` — строка видна на панели, — затем `phases/4-build.md`: там доводка выбранного варианта — все разделы, тексты с человеком, медиа и круги правок по живой странице до его «готово».

## Не делать

- Показывать круг, где превью ещё не собраны или не прошли `check.py`.
- Спрашивать «какой ближе», не открыв каждое превью по http и не проверив, что приём в нём работает (раздел 4, шаг 7): человек мог видеть пустые рамки или постер вместо видео.
- Давать человеку путь к файлу или адрес `file://` вместо `http://`.
- Подменять главный приём «намёком», стоп-кадром или подписью «здесь будет анимация», если материал есть или его можно получить; и молчать, если его действительно нет.
- Три разных тяжёлых ролика на три превью вместо одного общего лёгкого файла; генерировать в превью больше одной главной картинки на вариант без просьбы.
- Ставить `ask previews` до записи всех трёх вариантов: следующий `round option` тут же закроет ожидание, и часы пойдут.
- Три варианта одной раскладки, одной темы или одного семейства в разных цветах.
- Чужие фото, логотипы, скриншоты чужих сайтов в превью — только картинки человека, сгенерированные для него в бюджете или плашки «фото зала 4:5».
- Начинать сборку «пока он выбирает» или после выбора собирать сайт заново, выбросив код выбранного превью.
- Обсуждать с человеком семейства и оси словами дизайнера — он выбирает глазами.
