# Подготовка — Python, оснащение, режим, вход, панель, структура

Читается в начале прогона. Здесь по порядку: есть ли **Python**, чего не хватает на компьютере (**оснащение**), **режим**, **вход** («новый сайт» или «готовый сайт») и **форма вопросов**; поднимается панель, говорится открывающий блок, ставится недостающее, человек узнаёт, какие **генераторы картинок и видео** у него подключены, и раскладывается **структура** проекта. Таблица «событие → команда `ad.py`» в конце файла нужна на весь прогон.

## 0. Есть ли Python — до всего остального

Панель, проверки и бэкапы работают на Python 3.9+. Без него скилл дальше не идёт. Проверь сам:

| Система | Команда | Годится |
|---|---|---|
| Mac, Linux | `python3 --version` | `Python 3.9` и новее |
| Windows | `py -3 --version`, затем `python --version` | то же; ответ «Python was not found… Microsoft Store» — это заглушка, Python нет |

Годится — дальше везде, где написано `python3`, пиши ту команду, что ответила (`py -3` или `python` на Windows). Нет или версия старше 3.9 — **одно сообщение** человеку простыми словами и одна команда под его систему:

```
Чтобы я мог работать, на компьютере нужен Python — на нём работают панель, проверки и копии проекта. Сейчас его нет.
Поставь одной командой в Терминале:
  Mac:      xcode-select --install          (откроется окно — нажми «Установить»; заодно поставится git)
  Windows:  winget install --id Python.Python.3.12 -e --source winget
  Linux:    sudo apt install python3        (Fedora — sudo dnf install python3; Arch — sudo pacman -S python)
Когда закончится — напиши «готово».
```

- Называй только строку его системы. На Mac с Homebrew подойдёт и `brew install python`.
- **Пароль человек вводит сам, в своём Терминале**, не в чат: команды с `sudo`, установку Homebrew и установщики с запросом прав агент не запускает — только даёт строкой. Пароль в чате не просится никогда.
- После «готово» — проверь снова. Не появился — ещё раз одна строка, что не так (например, «открой новое окно Терминала — старое не видит Python»), и снова ждать.
- Панели ещё нет, `ad.py` не запущен — вопрос обычным сообщением, без `ask`.

## 1. Найти скилл и посмотреть, что стоит на компьютере

Найди папку навыка и скопируй учёт прогона в проект — остальные инструменты (`check.py` с частями `check_*.py`, `setup.py`, `backup.py`, `scaffold.py`, `designsystem.py`, `rules.py`, `shots.py`, `media.py`, `browser.py` с папкой `browser/`, `extract.py`, `pick.py` со справочником, `film.py`) скопирует сам `init`:

```bash
A=$(git rev-parse --show-toplevel 2>/dev/null || pwd -P)/.aidesign-work
TPL=$(find -L ~/.claude/skills ~/.agents/skills ~/.codex/skills ~/.cursor/skills ~/.gemini/skills \
        ~/.gemini/config/skills ~/.openclaw/skills ~/.claude/plugins \
        .claude/skills .agents/skills .cursor/skills .gemini/skills \
        -maxdepth 6 -path '*/aidesign/phases/dashboard-template.html' 2>/dev/null | head -1)
[ -n "$TPL" ] && TPL=$(cd "$(dirname "$TPL")" && pwd -P)/dashboard-template.html
command -v cygpath >/dev/null && TPL=$(cygpath -m "$TPL")   # Windows: C:/…, а не /c/…
SKILL_DIR=${TPL%/phases/*}; echo "skillDir = $SKILL_DIR"
mkdir -p "$A" && cp "$SKILL_DIR/tools/ad.py" "$A/ad.py"
```

- **Windows (Codex и другие агенты, у которых оболочка — PowerShell).** Команды этого файла написаны для bash: в Git Bash (ставится вместе с git) они работают как есть. Оболочка — PowerShell — вместо блока выше этот:

```powershell
$top = $null; try { $top = git rev-parse --show-toplevel 2>$null } catch {}
if (-not $top) { $top = (Get-Location).Path }
$A = Join-Path $top ".aidesign-work"
$TPL = "$HOME\.codex\skills", "$HOME\.agents\skills", "$HOME\.claude\skills", ".codex\skills", ".agents\skills", ".claude\skills" |
  ForEach-Object { Join-Path $_ "aidesign\phases\dashboard-template.html" } | Where-Object { Test-Path $_ } | Select-Object -First 1
$SKILL_DIR = Split-Path (Split-Path (Resolve-Path $TPL).Path); "skillDir = $SKILL_DIR"
New-Item -ItemType Directory -Force $A | Out-Null; Copy-Item "$SKILL_DIR\tools\ad.py" "$A\ad.py"
```

  Дальше в PowerShell `"$SKILL_DIR"/tools/…` пиши как `"$SKILL_DIR\tools\…"`, а `python3` — той командой, что ответила в разделе 0 (`py -3` или `python`). Копирование инструментов при продолжении (раздел 10) — `Copy-Item "$SKILL_DIR\tools\*.py", "$SKILL_DIR\knowledge\медиа\генераторы.json" .aidesign-work\` и папки — `Copy-Item -Recurse -Force "$SKILL_DIR\tools\browser", "$SKILL_DIR\knowledge\справочник" .aidesign-work\`.
- `skillDir` — абсолютный путь к папке навыка. Он уходит в `init` и живёт в `state.js`; от него строятся пути к `prompts/` и `knowledge/` для субагентов.
- `find -L` — навыки стоят через симлинки. Пусто → поищи один раз руками и продолжай.
- Шаблон панели и примеры работ скопирует сам `init` по `--skill-dir`. Шаблон руками не правится и в контекст не читается.

Затем — **проба без установки**, прямо из папки навыка (копий в проекте ещё нет):

```bash
python3 "$SKILL_DIR"/tools/setup.py doctor --need check
```

Таблица «программа · нужна · есть (версия) / нет · как поставить». Код 0 — обязательное есть, 1 — чего-то не хватает. Запомни, чего нет: спросишь об этом одним вопросом после панели (раздел 8).

И **браузерный модуль** — Playwright в общем кэше скилла, один на компьютер; им снимается стиль с сайта-референса (`extract.py`), идут правила раскладки на Проверке (`check.py --browser`) и снимки стыков фильма:

```bash
python3 "$SKILL_DIR"/tools/browser.py doctor
```

Код 0 — готов; 1 — печатает, чего нет (Node.js, пакет в кэше, браузер), и план; ставить — в том же вопросе раздела 8. `--need` добавляет нужное этому прогону: `check` — Chromium через Playwright для снимков; `video` — ffmpeg, когда на сайте будет видео (это видно позже, на Сборке); `figma` — только если человек сам заговорил о Figma.

## 3. Режим — если в вызове не назван

Слова режима считаются, только если стоят **в начале**, до текста задачи: `/aidesign auto лендинг кофейни`. В середине («лендинг, auto-подбор цветов») — это бриф.

| Режим | Слова |
|---|---|
| `auto` — «сам по брифу» | `auto`, «сам по брифу», «ничего не спрашивай», «полный автомат» |
| `important` — «только важное» | `important`, «только важное», «спроси только важное» |
| `interview` — «интервью» | `interview`, «режим интервью», «расспроси меня», «задай все вопросы» |

Не назван → один вопрос до `init`, выбором среды, если он есть, иначе списком; дождись ответа, до него ничего не делай (`ad.py` ещё не запущен — `ask` не нужен):

```
Как работаем? Ответь цифрой или словом:
1. Сам по брифу — соберу три превью по твоему описанию и референсам, вопросов почти не будет. Выбрать вариант всё равно попрошу тебя.
2. Только важное — спрошу 5–10 главных вещей о вкусе, остальное решу сам.
3. Интервью — подробно расспрошу о вкусе, стиле и тоне, тема за темой: вопросов будет 25–45, к каждому — мой вариант, обычно хватит ответить «ок». Спрашиваю по одному. Я бы выбрал это: так превью попадут в цель с первого круга.
```

Ответ мимо вариантов («как хочешь», «не знаю») → `interview`. «По одному» в ответе — это форма, режим тогда `interview`.

## 4. Вход и форма вопросов

- **Вход** ты определил сам (раздел 2) — не спрашивай. Спроси одной строкой только при противоречии: сайт в папке есть, а человек пишет «сделай новый сайт» — «В папке уже есть сайт. Переделываем его (а) или делаем новый рядом, в папке `new-site/` (б)?».
- **Форма вопросов** — по умолчанию «по одному» (`--questions one`). Сказал «пачками», «раундами», «по несколько» — `--questions rounds`. Отдельным стартовым вопросом не задаётся: карта интервью заканчивается вопросом о форме (`phases/2-interview.md`).

## 6. Открыть панель — один раз, сам

Сразу после `init`, до первого вопроса.

- **Claude Code, панель рядом с чатом:** `preview_start({url: "http://localhost:PORT"})`, затем `navigate` на `/dashboard.html`. Голый `navigate` на localhost без `preview_start` отклоняется. `file://` в панель не давай: превью и часы там не работают. Нет `preview_start` в списке инструментов — поищи его, прежде чем решить, что панели нет.
- **Claude desktop — ещё и обычный браузер.** Встроенный браузер приложения может не пускать живые превью в рамки панели: этапы и часы видны, а вместо вариантов — пустое место или строка «Этот браузер не показывает превью внутри панели». Поэтому в Claude desktop, кроме встроенной панели, сразу открой тот же адрес в системном браузере: `open http://localhost:PORT/dashboard.html` (Windows — `start "" http://localhost:PORT/dashboard.html`, Linux — `xdg-open …`). Там превью живые и кликаются.
- **Без панели (Codex и другие):** открой адрес `http://localhost:PORT/dashboard.html` в браузере (`open`, `xdg-open`, `start`). Превью видны **только через сервер** — по `file://` панель покажет подсказку открыть адрес.
- У каждого варианта на панели есть ссылка «Открыть в новой вкладке» — сам HTML превью; она работает в любом браузере.
- **Адрес назови в чате** всегда: некоторые клиенты показывают панель карточкой.
- `$SSH_CONNECTION` или `$CI` — назови путь, ничего не открывай. Не открылось — одна строка с адресом, и дальше.
- «Панель отвалилась» — один голый `python3 .aidesign-work/ad.py`: поднимет сервер на том же порту.

## 7. Открывающий блок

Один раз, после панели. **Подсказка, а не вопрос** — сказал и пошёл дальше.

```
Режим: интервью · вопросы по одному · вход: новый сайт.
Панель открыл: http://localhost:PORT/dashboard.html — там этапы, время работы, твои референсы и превью. На вкладке «Примеры работ» — что умеет AI Design.
Превью смотри в обычном браузере — я открыл панель и там. Не видно варианта — нажми под ним «Открыть в новой вкладке».   ← в Claude desktop
↑ Вышла версия AI Design 0.3.0 (у тебя 0.2.0): npx skills update aidesign -g   ← только если init её напечатал

Переключить можно в любой момент, просто скажи:
• «сам по брифу» — почти без вопросов, выбор превью всё равно за тобой
• «только важное» — спрошу только главное о вкусе
• «пачками» — по 3–4 вопроса в сообщении
• «дальше решай сам» — остановлю вопросы и решу сам, решения перечислю в конце
```

Строка «Превью смотри в обычном браузере» — только в Claude desktop, где панель открыта и во встроенном браузере, и в системном; в остальных клиентах её нет. Первая строка называет то, что включено на самом деле; в списке нет уже включённого режима; при форме «пачками» строка — «по одному». На готовом сайте третья фраза первой строки — «вход: готовый сайт — сначала посмотрю, как он устроен, ничего не сломаю». Есть `DESIGN.md` от прошлого прогона — строка «Продолжаю от направления «<name>» из `DESIGN.md`». Больше блок не повторяется; переключение посреди прогона — одна строка: «Понял, дальше только важное».

## 8. Оснащение — один вопрос об установке

По таблице `doctor` из раздела 1. Это первый вопрос после панели, если чего-то не хватает.

- **Нужно этому прогону:** всегда Python и git; Chromium через Playwright — для снимков на Проверке (ему нужен Node.js); Node.js — ещё если в проекте есть `package.json` или фреймворк. ffmpeg — только когда на сайте будет видео или много фото: спросишь на Сборке. Figma — только если человек её хочет.
- **Одним списком и одним вопросом**, перед ним — `python3 .aidesign-work/ad.py ask action --note "поставить недостающее"`:

```
Для работы на компьютере не хватает:
• git — история и откат (нужен всегда)
• Chromium через Playwright — снять сайт на телефоне и компьютере, проверить глазами
• браузерный модуль — снять стиль с сайта, который нравится, и проверить раскладку (ставится один раз, в папку скилла)
Ставлю официальными командами, по одной: всё (а), только обязательное (б) или ничего — работаю без этого (в)?
```

- **«а» или «б»** — браузерный модуль: `python3 .aidesign-work/browser.py ensure --yes` (ставит пакет в общий кэш скилла и проверяет браузер; без Node.js сначала Node через `setup.py`); остальное — `python3 .aidesign-work/setup.py install <имена> --yes`: ставит по одной, печатая каждую команду и итог. Команду, которой нужен пароль администратора, он не выполняет, а печатает строку «выполните в своём Терминале: …» и выходит с кодом 1 — дай человеку эту строку как есть, `ad.py ask action --note "жду: команда в Терминале"`, дождись «готово» и проверь снова `python3 .aidesign-work/setup.py doctor --need check`. Пароль в чат не просится.
- **Сбой** (код не 0 и не строка «в своём Терминале») — человеку код и последние строки вывода, без простыни, и развилка: «повторить (а), поставлю сам (б), пропустить (в)». Сеть отвалилась — та же развилка. Ничего не удаляется; частично поставленное покажет повторный `doctor`.
- **«в» или отказ от части** — работай дальше, отказанное заменяется: нет Playwright — проверка браузером агента или без снимков, и это строка в отчёте (`ad.py add report "…"`); нет git — копии проекта всё равно делает `backup.py`. Нет браузерного модуля — стиль по ссылке снимается браузером агента или по скриншотам, правила раскладки на Проверке — глазами.
- Итог — одной командой (браузерный модуль в списках — словом `browser`): `python3 .aidesign-work/ad.py toolkit set --missing <чего нет> --installed <что поставили> --skipped <от чего отказались>` (списки через запятую; пустой список не передаётся). На панели в Подготовке появится строка «Оснащение».

Всё нужное уже стоит — вопроса нет: `python3 .aidesign-work/ad.py toolkit set` без списков (оснащение проверено, не хватает ничего).

### Генераторы картинок и видео — что подключено

Сразу после оснащения, без вопроса: это факты, их находишь сам. Подробности — `knowledge/медиа/генераторы.md`, разделы 1–2.

1. **Список своих инструментов** — всё, что реально есть в этой сессии: MCP вида `mcp__<сервер>__<инструмент>` и встроенные (например, `image_gen` в Codex). Если среда прячет часть инструментов до поиска, поищи по словам `image`, `video`, `generate`, `3d`, `audio`. По памяти и по прошлым сессиям не дописывай. Запиши по имени в строке в `.aidesign-work/<dir>/tools.txt`.
2. `python3 .aidesign-work/media.py detect --tools-file .aidesign-work/<dir>/tools.txt --json` — подключённые генераторы: что умеют (картинки, видео, звук, 3D, вектор), какими инструментами смотреть баланс, цену, ждать и скачивать. Незнакомый сервер с «image», «video», «generate» в именах тоже попадёт — как неизвестный (`known: false`): им можно пользоваться, но его правила читай в инструкциях самого сервера.
3. Нашлось — `python3 .aidesign-work/ad.py media connected --ids <id через запятую>`: на панели появится блок «Медиа». Не нашлось — вызов не нужен.
4. `python3 .aidesign-work/media.py skills` — установленные у человека скиллы и инструкции про промпты и медиа (например, aimaster): имя, что умеет, путь к главному файлу. Запомни — по ним пишутся промпты на Превью и Сборке.
5. **Баланс** — только если у сервиса есть инструмент баланса (это бесплатно) и он ответил. Цену и баланс не угадывай.

Человеку — одно сообщение-подсказка, не вопрос:

```
Подключено для картинок и видео:
• Higgsfield — картинки, видео, 3D · баланс 1 240 кредитов
• встроенная генерация Codex — картинки
Инструкции по промптам: aimaster (Nano Banana, Seedance, Kling и другие) — возьму оттуда.
Генерация платная: перед первой спрошу, сколько готов потратить, и дальше буду держаться этой суммы. Свои фото и видео лучше любых сгенерированных — в интервью спрошу, есть ли они.
```

Ничего не подключено — строка: «Генераторов картинок и видео не вижу — не страшно: возьму твои фото, фон и частицы сделаю кодом, где нужно фото — поставлю подписанную плашку. Хочешь генерацию — скажи, подключим одной командой».

**Подключить нужный** — человек назвал сервис, которого нет (сейчас или в интервью): `python3 .aidesign-work/media.py connect <id> --host claude` (в Codex — `--host codex`) печатает официальную команду и что сделать со входом. Перед вопросом — `ad.py ask action --note "подключить <сервис>"`; команду выполняешь **только после «да»**; вход в аккаунт (браузер, ключ) человек делает сам, ключи в чат не просятся и в файлы не пишутся. Новые инструменты появляются после перезапуска среды — одна строка: «Подключил. Перезапусти меня и напиши «продолжи AI Design»»; прогон не закрывается, продолжение — раздел 10. Неизвестный сервис — общий шаблон из `connect` и ссылка на его документацию, ничего не выдумывая.

## 9. Структура проекта

```bash
python3 .aidesign-work/scaffold.py plan --root . --kind page    # одна страница; несколько страниц — --kind site
```

`page` или `site` — по брифу («лендинг», «блок», «презентация» — page; «сайт», «несколько страниц» — site); не ясно — `page`, `apply --kind site` позже допишет только `pages/`. Где что лежит и почему — `knowledge/структура-проекта.md`.

- **Пустая папка** (или только `референсы/`) — сразу `python3 .aidesign-work/scaffold.py apply --root . --kind page --title "<название>"` (с `--git`, если git стоит, а репозитория нет: `git init` и коммит «До AI Design»). Человеку одна строка: «Разложил проект: страница, стили, дизайн-система, правила для агентов. Завёл историю git — состояние «до» сохранено». `--git` вернул код 1 (git не знает имени) — имя и почту не выдумывай: одна строка, как их задать (`git config --global user.name "…"`), и дальше без коммита.
- **Папка с файлами, но не сайт** (картинки, тексты вперемешку) — сначала бэкап «до»: `python3 .aidesign-work/backup.py create --root . --reason "до-структуры"` и `ad.py backup add` с его `id` и размером; затем `apply`. Свои файлы человека не перекладываются молча — список «что куда», перенос после «да».
- **Готовый сайт** — только `plan`: одна строка человеку, чего не хватает по схеме («нет папки дизайн-системы и правил для агентов — заведу на Сборке, после копии проекта»). Раскладка работающего сайта (`index.html`, `assets/`, `pages/`) помечена `propose` — переносится только с согласия, на Сборке (`phases/4-build.md` §4).
- **Блок `aidesign` обновляется сразу после каждого события**, которое меняет проект, и «структура создана» — первое из них. Нового `AGENTS.md` `apply` уже пишет с коротким блоком. Факты блока — подраздел «Сейчас» — дальше ведёт `ad.py` сам после `direction set`, `backup add`, `figma set`, `toolkit set`, `stage build|check|handoff done` и `finish`: файла памяти или блока нет — заведёт по правилу `phases/6-handoff.md` §2 (был только `CLAUDE.md` со своим текстом — блок в его конец, `AGENTS.md` рядом не появится), в `GEMINI.md`, `.cursorrules` и другие файлы правил агентов допишет строку-указатель. На готовом сайте он не трогает файлы человека до первой копии «до». «Сейчас» руками не правь; правила блока (что можно, чего нельзя) пишешь ты, как и куда — там же, §2.

Затем — `ad.py stage refs` и `phases/1-refs.md`.

## 10. Продолжение прерванного прогона

«Продолжи AI Design», голый `/aidesign` или `init` отказался:

1. Прочитай `state.js` (`dir`, `skillDir`, режим, форма, вход, этапы, круги, `waiting`, `backups`, `toolkit`, `figma`), затем файлы прогона из «После сжатия контекста» в `SKILL.md`.
2. Перекопируй `ad.py` (раздел 1) и инструменты: `cp "$SKILL_DIR"/tools/*.py "$SKILL_DIR"/knowledge/медиа/генераторы.json .aidesign-work/` и папки `cp -R "$SKILL_DIR"/tools/browser "$SKILL_DIR"/knowledge/справочник .aidesign-work/`; подними панель голым `python3 .aidesign-work/ad.py`; открой её заново (раздел 6) — вкладка не переживает сессию.
3. Одна строка человеку: где остановились и что дальше — «Остановились на круге 2: ты сказал, что в Б нравится шрифт. Собираю круг 3». Висит `waiting` — повтори тот вопрос, с `ask`.
4. Продолжай с файла активного этапа.

**Человек просит новое, а прерванный прогон есть** (например, «причеши сайт», а висит прошлый незаконченный круг превью) — не продолжай молча и не затирай: один вопрос с вариантами, до `init` (`ask` ещё не нужен): «Есть прерванный прогон «<title>» — остановились на <этап>. Продолжаем его (а) или начинаем заново — старый останется в архиве (б)?». «а» — шаги 1–4 выше; «б» — `init … --force`: прошлый `state.js` уходит в папку своего прогона, его файлы не удаляются. Его `refs.md` и `vkus.md` — отправная точка нового: скопируй в новую папку прогона и в интервью подтверди одной строкой («Профиль прошлого раза: … Оставляем?»), а не спрашивай всё заново; готовый материал прошлых кругов (ролики, кадры) — тоже его, без новой генерации.

## 11. Одно событие — один вызов

Все вызовы — `python3 .aidesign-work/ad.py …`; время ставит сам скрипт.

| Событие | Вызов |
|---|---|
| начался этап | `ad.py stage <id>` — прошлый закроется сам; id: `preflight refs interview previews build check handoff` |
| этап осознанно пропущен | `ad.py stage <id> skip --note "причина"` |
| этап не удался | `ad.py stage <id> fail --note "что мешает"` |
| режим, форма или вход поменялись | `ad.py set mode=auto` · `ad.py set questions=rounds` · `ad.py set questions=one` · `ad.py set entry=existing` |
| ждём человека | `ad.py ask refs\|interview\|previews\|action\|stop --note "что ждём, одной строкой"` — **перед** сообщением с вопросом |
| человек ответил | `ad.py answered` — или ничего, если следующий вызов `stage`, `round`, `direction`, `check`, `finish`: они закрывают ожидание сами |
| референс получен | `ad.py ref add --path P --kind image\|screenshot\|url\|text --note "что на нём"` · уточнить — `ad.py ref note --i N --note "…"` |
| тема интервью | `ad.py theme add --id tone --title "Тон"` · `ad.py theme set --id tone --status asked\|answered\|decided` |
| круг превью | `ad.py round new` · `ad.py round option --id a --title "…" --src rounds/NN/a.html --note "…"` · `ad.py round feedback --text "…"` · `ad.py round choose --id b` (или `none`) · `ad.py round refine --id a` |
| направление выбрано | `ad.py direction set --name "…" --summary "…" --file DESIGN.md` |
| итог проверки | `ad.py check --findings N --fixed N` |
| оснащение проверено или поставлено | `ad.py toolkit set --missing a,b --installed c --skipped d` |
| сделана копия проекта (`backup.py create` напечатал id и размер) | `ad.py backup add --id ID --reason "до" --bytes N` — id и команда отката сами попадут в «Сейчас» блока `aidesign` |
| Figma подключена, файл обновлён | `ad.py figma set --url <ссылка на файл> --mode free\|paid` |
| генераторы найдены (`media.py detect`) | `ad.py media connected --ids higgsfield,magnific` |
| человек выбрал, откуда медиа | `ad.py media sources --set own\|generate\|mixed\|code\|placeholder` |
| человек назвал бюджет на генерацию | `ad.py media budget --limit N --unit кредитов` (единица — та, в которой сервис считает) |
| перед платной генерацией | `ad.py media check --amount N` — код 0 в бюджете, 1 — выйдет за сумму или бюджета нет; ничего не записывает |
| генерация прошла | `ad.py media spend --service <id> --amount N --unit <как в бюджете> --item "<место>"` |
| допущение за человека, строка в отчёт | `ad.py add assumptions "…"` · `ad.py add report "…"` |
| прогон сдан | `ad.py finish --result "одна строка: что теперь есть" --check-update` |

- **`ask` — это «Ждём тебя» на панели** и остановка часов. Вопрос без `ask` оставляет часы идти, как будто идёт работа.
- **`round …` и `stage …` закрывают ожидание.** Поэтому в круге превью `ask previews` ставится **после** трёх `round option`, прямо перед сообщением человеку (`phases/3-previews.md`).
- Строки `!` в выводе — бухгалтерия: исправь одним вызовом в том же ходе, не расследуй.
- Ни одного значения секрета ни в одном вызове.
